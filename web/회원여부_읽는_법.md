# 회원 여부를 읽는 법

2026-09-25. 하루에 같은 버그를 네 번 고쳤습니다. 그 네 번이 전부
**두 값으로 판정한 자리**였습니다. 이 문서는 그것을 다시 안 만들기 위한 것입니다.

---

## 한 줄 요약

```
회원 여부는 세 값입니다 — 회원 · 비회원 · 모름.
「모름」은 빈 자리입니다. 가입 권유도 회원 자료도 그리지 않습니다.
```

---

## 1. 벽이 두 종류입니다

섞으면 안 됩니다. 막는 힘도 문구도 다릅니다.

| | 세션 벽 | 설문 벽 |
|---|---|---|
| 무엇으로 | 로그인했나 | `profiles.survey_at` 이 찍혔나 |
| 누가 막나 | **DB** 가 막습니다 (RLS · 실행 권한 · `42501`) | **화면만** 가립니다. 자료는 이미 와 있습니다 |
| 어디에 | `serverWho` · `app/jobs/page.tsx` · `components/org-stat.tsx` | `app/gate.tsx` · `components/job-veil.tsx` |
| 뚫리나 | 안 뚫립니다. 요청을 직접 만들어도 안 옵니다 | 개발자도구를 열면 다 보입니다 |
| 문구 | 「가입하고 전부 보기」 → `/login` | 「3분 설문 마치고 전부 보기」 → `/welcome` |

**로그인한 사람에게 「가입하고 전부 보기」를 보이면 안 됩니다.**
누르면 로그인 화면이 나와 「이미 로그인되어 있어요」가 뜹니다.
2026-09-25 에 실제로 그랬습니다.

`components/org-stat.tsx` 한 곳만 둘이 겹칩니다 — 로그인 안 했으면 자물쇠,
로그인했는데 설문 전이면 그 위에 흐림.

---

## 2. 세 값과 그 뜻

이름과 뜻이 **서버와 화면에서 같아야** 합니다. 다르면 맞춰볼 수가 없습니다.

```
회원    로그인했습니다
비회원  로그인 안 했습니다 — **물어봤고 아니라는 답을 받았습니다**
모름    **물어봤는데 답을 못 받았습니다** (연결 끊김 · 토큰 갱신 실패 · 아직 확인 중)
```

| 어디 | 무엇을 씁니까 |
|---|---|
| 서버 | `serverWho(sb)` — `lib/supabase-server.ts` |
| 화면 | `useAuth().who` — `app/auth.tsx` |
| 설문 | `useAuth().설문` — `'마침' / '안마침' / '모름'` |
| 가리기 | `useGate()` — `app/gate.tsx`. **여기 하나만 쓰세요** |

`Who` 라는 이름은 `lib/supabase-server.ts` 한 곳에만 있습니다.
화면에서는 `import type { Who }` 로 **모양만** 가져옵니다 — 이름표를 두 벌 만들지 않습니다.

---

## 3. 「모름」이면 무엇을 그리나

**자리를 비웁니다.** 가입 권유도, 회원 자료도, 흐림도 그리지 않습니다.

서버 세 곳이 전부 이 방향입니다 (2026-09-25 에 맞췄습니다).

```
app/jobs/[id]/page.tsx     who === '모름' → null
app/orgs/page.tsx          who === '모름' → null
components/org-detail.tsx  who === '모름' → null
```

전에는 뒤 둘이 **회원 쪽으로 넘어갔습니다.** 그러면 자료가 빈 채로 그려져
「찾는 결과가 없습니다」처럼 보입니다 — 없는 사실을 지어내는 꼴입니다.

## 4. 새 화면을 만들 때 (복사해서 쓰세요)

### 서버에서 그리는 화면

```tsx
const sb = await serverSupabase();
const who = await serverWho(sb);

if (who === '모름') return null;          // ← 빼먹지 마세요
if (who === '비회원') return <MembersOnly … 진단="이 파일 이름" />;

// 여기부터 회원
```

### 화면(client)에서 가리는 자리

```tsx
const { 모름, full, 회원, href } = useGate();
if (모름) return null;                    // ← 빼먹지 마세요
if (full) return <>{children}</>;
// 여기부터 맛보기 + 권유. 문구는 회원 이냐로 갈립니다
```

### 눌렀을 때

```tsx
const { loading, session } = useAuth();

async function 눌렀을때() {
  if (loading) return;                    // ← 기다립니다. /login 으로 보내지 마세요
  if (!session) return toLogin();
  …
}
```

## 5. 하지 말 것 — 네 번 다 이것이었습니다

```js
// ✗ 오류를 버립니다. 실패해도 user 가 null 이라 비회원과 구분이 안 됩니다
const { data } = await sb.auth.getUser();
if (!data.user) → 가입 권유

// ✗ 못 읽은 것을 「가입 안 함」으로 셉니다
setMe(prof.data ?? null);

// ✗ 확인 중을 비회원으로 그립니다 (loading 을 안 받음)
const { session, me } = useAuth();

// ✗ 오류가 나면 로그아웃시킵니다 — 잠깐 끊긴 것만으로 로그인이 풀립니다
if (error || !data.user) await sb.auth.signOut({ scope: 'local' });
```

핵심은 하나입니다.

> **「아니다」와 「모르겠다」는 다른 답입니다.**

`42501`(권한 없음)은 **물어봐서 받은 답**이라 「비회원」으로 써도 됩니다.
연결이 끊긴 것은 답이 아닙니다.

## 6. 고친 뒤 돌릴 것

```
node tools/check-gate.mjs     가리는 규칙 여섯 칸
npx tsc --noEmit
npx next build                화면 성질(정적/동적)이 안 바뀌었는지도 함께
```

`check-gate.mjs` 는 `app/gate.tsx` 의 `gateOf` 원문도 같이 대조합니다.
규칙을 고치면 검사도 같이 고치라고 알려줍니다. **두 벌이 되는 순간
검사가 거짓말을 하기 때문입니다.**

---

## 7. 화면에서 직접 보는 법

주소 끝에 `?진단=1` 을 붙입니다.

```
…/orgs?진단=1        …/jobs/<번호>?진단=1
```

화면 맨 아래에 서버 판정과 화면 판정이 나란히 뜨고, 가입 권유 카드마다
그것을 그린 파일 이름과 판정 재료가 붙습니다.
쿠키 값·토큰·사람 id 는 안 찍습니다 — 있음/없음과 개수만입니다.

관리자에게만 보이게 하지 않았습니다. **관리자인지 아는 방법이 바로
고장나는 그 판정**이라, 고장났을 때 진단판도 같이 안 보이기 때문입니다.
