> **두 자리의 값이 다르면 이런 증상이 납니다** —
> ① **Supabase 쪽만 옛것**: 로그인 자체가 안 됩니다. 애플이 `invalid_client`

>    실패합니다.** 회원은 아무것도 못 느끼고 애플 심사에서 걸립니다.
>    그래서 **둘을 같은 값으로** 두고 **같이** 바꿉니다.

**그물** — `docs/만료일.json` 에 적어 두었고
`.github/workflows/만료일점검.yml` 이 날마다 읽어 **2주 전(2027-03-29)부터**

## ⑧ 탈퇴할 때 애플 연결 끊기 — ✅ **2026-10-11 에 붙였습니다**

애플 **5.1.1(v)** — 탈퇴하면 애플 쪽 연결도 끊어야 합니다
(`POST https://appleid.apple.com/auth/revoke`).

### 어떻게 돌아가나

```
① 애플로 로그인하고 돌아온 **그 순간**에만 세션에 provider_refresh_token 이
   실려 옵니다. /auth/callback 이 창구 애플연결저장() 으로 넣어 둡니다
② 탈퇴할 때 /api/apple-revoke 가 내애플연결() 로 **그 사람 것만** 꺼내
   애플에 revoke 를 부릅니다
③ 끝나면 애플연결끊음() 이 값을 비웁니다 (지우지 않습니다)
```

표 `애플연결` 은 **창구로만** 봅니다 (정책 0개 · anon·authenticated 권한 없음).

### 세중님이 넣으실 것 — **서버가 아니라 Vercel 입니다**

`revoke` 는 **화면 쪽 자리(/api/apple-revoke)**가 부릅니다. 그래서 열쇠는
**Vercel** 에 둡니다 (서버 `.env` 가 아닙니다 — 제가 앞에 잘못 적었습니다).

```
Vercel → potjob-web → Settings → Environment Variables → Production
  APPLE_CLIENT_ID       kr.co.potjob.web
  APPLE_CLIENT_SECRET   ⑤ 에서 만든 **JWT 전체** (apple_secret.txt 의 글)
→ 넣은 뒤 **다시 배포**해야 값이 붙습니다
```

> **.p8 이 아니라 JWT 를 둡니다.** .p8 을 두면 「아무 때나 새 비밀을 만들 수
> 있는 열쇠」가 거기 있게 됩니다. 6개월짜리 JWT 만 두는 쪽이 샜을 때 피해가
> 작습니다. **⑦ 에서 6개월마다 JWT 를 새로 만들 때 이 값도 함께** 바꿉니다 —
> 안 바꾸면 **탈퇴할 때 연결 끊기만 조용히 실패합니다.**

**지금 안 넣어도 탈퇴는 됩니다** — 열쇠가 없으면 그 자리가
「애플 열쇠가 아직 없습니다」만 돌려주고 탈퇴는 그대로 갑니다.
애플 로그인을 쓴 적 없는 분에게는 애초에 할 일이 없습니다.
