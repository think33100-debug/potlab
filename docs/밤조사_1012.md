### 합치는 방안 — **수집기 목록 → DB** 한 방향

DB 를 기준으로 삼되, **값은 수집기 목록에서 옮겨 심습니다.** 반대로 하면
채용게시판 주소와 긁는 규칙을 전부 잃습니다.

**낮에 승인받을 SQL (아직 안 돌렸습니다 · 밤 규칙)**

```sql
-- ① 긁는 규칙을 담을 칸을 더합니다. 기존 칸은 한 글자도 안 건드립니다.
alter table public.hosp_sites
  add column if not exists 채용주소   text,          -- 수집기의 url  (게시판 주소)
  add column if not exists 갈래       text,          -- type  html|appsite|listjson|cmc|schmc|greeting
  add column if not exists 긁는규칙   jsonb not null default '{}'::jsonb,
                                                     -- row·link·only·not·enc·host·base·cls·clsTitle·dept
  add column if not exists 끔         boolean not null default false,
  add column if not exists 끈까닭     text,
  add column if not exists 집에서만   boolean not null default false,   -- athome
  add column if not exists 옮긴날     date;

-- ② 옮기기는 **창구 함수로** 합니다 (표에 직접 쓰지 않습니다).
--    p_rows 는 tools/hosp/hosp-sites.json 을 그대로 넣습니다.
create or replace function public.기관사이트_옮기기(p_secret text, p_rows jsonb)
returns jsonb language plpgsql security definer set search_path = public as $$
declare v_n int := 0;
begin
  if p_secret is null or p_secret <> current_setting('app.collect_key_hs3', true) then
    raise exception '열쇠가 다릅니다';
  end if;
  update hosp_sites s set
    채용주소 = r->>'url',
    갈래     = r->>'type',
    긁는규칙 = (r - 'name' - 'url' - 'type' - 'off' - 'athome'),
    끔       = coalesce((r->>'off') is not null, false),
    끈까닭   = r->>'off',
    집에서만 = coalesce((r->>'athome')::boolean, false),
    옮긴날   = (now() at time zone 'Asia/Seoul')::date
  from jsonb_array_elements(p_rows) r
  where s.name = r->>'name';
  get diagnostics v_n = row_count;
  return jsonb_build_object('옮긴 곳', v_n, '넣은 줄', jsonb_array_length(p_rows));
end $$;

revoke execute on function public.기관사이트_옮기기(text, jsonb) from public, anon;
grant  execute on function public.기관사이트_옮기기(text, jsonb) to service_role;
```

> `delete` · `drop` 글자가 없습니다 — 승인 창이 뜨지 않을 것으로 봅니다
> (지침 8-7). 그래도 **전문을 먼저 보여 드리고 확인받은 뒤** 올립니다 (지침 8-8).

### ③ 마감일 없는 공고가 지금 어떻게 보이나

```
회원 화면 전체            358건
마감일 없음                41건   (HS 39 · ND 2 — 날짜를 주는 출처는 0건)
  「수시채용」 으로 보임        3건
  「마감일 공고문 확인」 으로     38건
```

`마감표시()` 는 이렇습니다 (DB 원문).

```
apply_to 가 있으면                   → 날짜를 그대로 보여줍니다
공공기관인가()                        → 「마감일 공고문 확인」
제목·접수문장에 채용시까지|상시|수시|충원시|결원시  → 「수시채용」
그밖                                 → 「마감일 공고문 확인」
```

### ④ 언제 내려가나 — **안 내려갑니다**

`hide_stale_posts(p_days, p_rolling_days)` 를 읽었습니다. 마감일이 없는 공고는
처음 본 지 `p_days`(30일)이 지나면 감추는데, **단서가 붙어 있습니다** —

```
and not (seen_on >= 오늘 - 14 and coalesce(gone_streak,0) = 0)
        └ 「정찰이 아직 그 사이트에서 보고 있다」 면 안 내립니다
```

병원이 몇 해 전 글을 게시판에서 **안 내리면** 정찰은 영영 「살아 있다」고 봅니다.

| 곳 | 처음 본 날 | 며칠 | 오늘 사이트에 | 줄의 상태 |
|---|---|---|---|---|
| 포천우리병원 | 2022-05-18 | **1,608** | 아직 있음 | 상태말 없음 |
| 더자인병원 | 2024-08-20 | 783 | 아직 있음 | 상태말 없음 |
| 한일병원 | 2025-07-31 | 438 | 아직 있음 | 상태말 없음 |
| 한일병원 | 2025-08-20 | 418 | 아직 있음 | 상태말 없음 |
| 뉴고려병원 | 2025-12-19 | 297 | 아직 있음 | 상태말 없음 |

**「사이트 목록에서 사라졌을 때 숨기기」 로는 이 다섯 건을 못 잡습니다.** 아직
올라와 있기 때문입니다. 열 건을 짚어 보니 그 규칙으로 잡히는 것은 **1건뿐**이었습니다.

### ⑤ 제안 — 세 가지를 **따로** 걸어야 합니다

하나로는 안 됩니다. 신호가 서로 다릅니다.

```
㉮ 줄의 상태를 읽습니다  (가장 값이 큽니다 — 11건 + 앞으로 들어오는 것)
   hospParseHtml 이 줄을 자를 때 그 줄 글에 마감|종료|완료|채용마감|모집완료 가
   있고 접수중|진행중|채용중|모집중 이 없으면  → rows[].상태 = '마감'
   · 수집기는 그 줄을 **담지 않습니다** (지금 「마감 지난 것」 과 같은 자리)
   · 이미 담긴 것은 **되메우기**로 내립니다 (낮 일 · updated_at 안 건드림)
   · 그 줄에 둘 다 있거나 같은 제목 줄이 여럿이면 **건드리지 않습니다**
     (오늘 2+2건이 그랬습니다. 애매하면 그냥 둡니다)
   · 상태 표시가 있는 113곳에서만 돕니다. 나머지엔 영향이 없습니다

㉯ 사라지면 내립니다  (6건)
   gone_streak 은 **이미 있습니다.** 지금은 「처음 본 지 30일」 이라는 바닥 때문에
   사라져도 최대 30일 더 보입니다.
   → 마감일이 없고 gone_streak ≥ 3 (사흘 내리 안 보임) 이면 날수와 **무관하게** 감춤

㉰ 날수 뚜껑  (5건 · 포천우리 1,608일)
   마감일이 없고 처음 본 지 N일이 넘으면 **정찰이 살아 있어도** 감춥니다.
   N 을 정하셔야 합니다 — 90일이면 위 다섯 건 전부, 180일이면 넷이 내려갑니다.
   그 사이트가 글을 안 내리는 것이고, 1,608일 된 공고는 회원에게 거짓입니다
```

## 제가 잡은 제 실수 셋

보고에 쓴 숫자가 바뀐 것이 있어 적습니다.

### ① 쪽을 넘기며 **고유하지 않은 칸**으로 정렬해 줄이 새어 나갔습니다

```
처음   job_posts?…&order=first_seen.desc  를 Range 로 100줄씩
무슨 일  같은 날짜가 수십 건이라 쪽마다 동률의 순서가 흔들려 **일부 줄이 빠졌습니다**
드러난 곳 청주성모 「물리치료사 채용」(HS1438877331)이 DB 에 멀쩡히 있는데
         2,317건 안에 안 들어와 → 「사이트에 있는데 우리 DB 에 없다」 **헛경보**
고친 뒤  order=id.asc 로만 넘기고, Prefer: count=exact 로 받은 줄 수가
         실제와 같은지 **확인하고 안 맞으면 멈춥니다**
```

이 때문에 「어디에도 없음」 이 205 → **196** 으로, 「진짜 놓침」 이 2 → **1** 로
줄었습니다. 바로잡은 값이 위 표의 값입니다.

### ② `job_posts_pub.title` 은 **다듬은 제목**입니다

사이트 제목과 견줄 것은 `원문제목` 칸입니다.

```
job_posts_pub.title   「청주성모병원 물리치료사 채용공고」      ← 회원에게 보여줄 꼴
job_posts_pub.원문제목  「물리치료사 채용」                    ← 사이트에 적힌 그대로
```

처음에 `title` 로 견주어 **46건 중 38건이 「사이트 목록에 없음」** 이라고 나왔습니다.
당연합니다 — 사이트에는 그런 제목이 없습니다. 바로잡으니 6건입니다.

### ③ 줄을 **고를** 때 괄호 안을 버려 엉뚱한 줄에 붙었습니다

```
우리 공고   부산광역시의료원 「직원 모집 공고(물리치료사 - 기간제)」
괄호를 버리니 「직원모집공고」 → **「직원 모집 공고(기록물관리 전문요원 - 행정직)」** 줄에 붙음
그 줄이 「완료」 라서 우리 물리치료사 공고를 마감으로 셌습니다
```

괄호를 살려 다시 세니 **제대로 된 줄**에 붙었고 (`1181 완료 직원 모집
공고(물리치료사 - 기간제)`) 결과는 같았지만, 근거가 틀린 것이었습니다.
「있나 없나」만 볼 때는 느슨한 쪽이 맞고, **줄을 고를 때는 괄호를 살려야** 합니다.
