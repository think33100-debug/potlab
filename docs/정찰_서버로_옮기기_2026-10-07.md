# 정찰(원문 살아있나)을 서버로 — 그리고 GitHub 쪽 끄기

**2026-10-12 에 새로 썼습니다.** 크론 주석과 마이그레이션 글이 이 파일을
가리키고 있었는데 **저장소에 없었습니다** (git 이력에도 없습니다). 지금 상태를
그대로 적습니다. 지침 6절의 결입니다 — 문서가 가리키는 것이 없으면 없는 기능입니다.

## 정찰이 하는 일

마감일이 **없는** 공고(「수시모집」 「상시」)는 날짜로 끝을 알 수 없습니다.
그래서 원문을 직접 열어 봅니다. 답은 넷입니다.

```
alive    글이 있습니다                         → gone_streak 0 · seen_on 오늘
gone     404 · 「존재하지 않는 글」 · 목록으로 튕김 → gone_streak +1, **두 번 연속**이면 감춤
closed   제목·본문·**목록 줄**에 마감 표시        → 바로 감춤 (까닭을 적습니다)
unknown  타임아웃 · 5xx · 막힘                  → **아무것도 안 바꿉니다**
```

`unknown` 을 따로 두는 까닭 — 사이트가 잠깐 아픈 것을 「없어졌다」로 세면
멀쩡한 공고가 사라집니다. 두 번 연속으로 보는 까닭도 같습니다.

보는 신호는 여섯입니다 (`tools/alive.mjs`).

| | 무엇 | 언제 더했나 |
|---|---|---|
| ① | HTTP 404·410 · 본문의 「존재하지 않는 글」 | 처음부터 |
| ② | **제목**에 `마감·채용완료·모집종료·접수마감·채용종료` | 2026-10-07 |
| ③ | 본문 「접수기간 : \<마감\>」 | 2026-10-07 |
| ④ | 본문 「접수기간」 뒤 60자에서 마감일 읽기 | 2026-10-07 |
| ⑤ | 목록 쪽으로 튕김 (307) | 2026-10-07 |
| ⑥ | **목록 줄의 상태 칸** (`채용완료`·`모집완료`·`완료`…) | **2026-10-12** |

②는 「우리가 담은 제목 토막이 그 줄에 같이 있어야」 라는 가드가 있습니다 —
옆 글의 「(마감)○○ 채용공고」 를 보고 엉뚱한 판정을 하지 않게.
⑥의 규칙은 `tools/hosp/hs_목록상태.mjs` 한 곳에 있고, 조사 도구
`tools/마감표시_줄마다.mjs` 도 **같은 함수**를 씁니다 (지침 6절).

쓰는 창구는 둘입니다 — `alive_targets(p_secret, p_n, p_내린것)` 로 볼 것을 받고,
`alive_mark(p_secret, p_rows)` 로 적습니다. 날짜 읽기는 DB 의
`deadline_from_title()` 한 벌이 합니다.

## 어디서 도나 — **서버 한 곳**입니다 (2026-10-12 부터)

```
서버 크론    15 2 * * *   node tools/alive.mjs      날마다 02:15 · SUPABASE_SERVICE_KEY
             (2026-10-12 에 timeout -k 30 1800 을 걸었습니다)
GitHub       .github/workflows/alive.yml            **schedule 을 껐습니다**
             손으로 돌리기(workflow_dispatch)는 그대로 됩니다
```

### GitHub 쪽을 끈 까닭 (2026-10-12 세중님 결정)

```
① 겹치기였습니다 — 서버가 **날마다** 돕니다. GitHub 은 주 1회(월 05:40)였습니다
② 그 워크플로만 **anon 열쇠**로 돌았습니다. service_role 열쇠는 GitHub 에
   넣지 않는 규칙이라, 그것 때문에 alive_targets·alive_mark 의 anon 을
   못 걷고 있었습니다
③ 결과를 대조할 수가 없었습니다 — 박동(collector_beat)이 2026-10-07 에
   더해졌고, 그 뒤 월요일은 **2026-10-12 하루뿐**입니다. 그날 05:40 박동이
   **없습니다.** alive.mjs 는 볼 것이 0건이어도 박동을 남기므로,
   그 워크플로는 alive.mjs 에 **닿지 못했습니다**
   (gh 가 집·서버 둘 다 없어 Actions 이력은 못 읽었습니다)
```

끈 뒤 권한을 걷었습니다.

| 함수 | 2026-10-12 아침 | 지금 |
|---|---|---|
| `alive_targets(text,int,bool)` | **`=X/postgres`(PUBLIC)** · postgres · service_role | postgres · service_role |
| `alive_mark(text,jsonb)` | postgres · service_role · anon · authenticated | postgres · service_role |
| `alive_targets(text,int)` (옛 2인수판) | 그대로 | postgres · service_role · anon · authenticated |

2인수판은 부르는 곳이 없습니다 — `alive.mjs` 는 늘 `p_내린것` 을 넘겨
**3인수판**을 씁니다. 치우는 것은 따로 여쭙니다.

### 되살리려면

```
1. .github/workflows/alive.yml 의 schedule 세 줄 주석을 풉니다
2. grant execute on function public.alive_targets(text,integer,boolean) to anon;
   grant execute on function public.alive_mark(text,jsonb) to anon;
```

## 멀쩡한지 보는 법

```
박동      select * from collector_beat where source='ALIVE' order by ran_at desc limit 5;
          늦음 기준 36시간 (평소 간격이 24시간입니다)
로그      ssh potjob 'tail -40 ~/log/정찰.log'
한 번 돌려 보기
          ssh potjob 'cd ~/potlab && set -a && . ./.env && set +a \
            && node tools/alive.mjs --dry --n 3'
          → 「── 살아 있음 N · 사라짐 N · 마감됨 N …」 과
            「목록 줄 — 받은 기관 N · 못 받은 기관 N · 판정 …」 이 찍혀야 합니다
```

**주의** — `alive_targets` 는 `seen_on` 이 6일 안인 공고를 건너뜁니다. 그래서
규칙을 새로 넣어도 **최근에 본 공고에는 최대 6일 동안 안 걸립니다.**
한 번 따라잡아야 하면 `tools/목록마감_내리기.mjs` 를 씁니다 (⑥ 전용).

`--내린것` 은 평소에 붙이지 않습니다 — 날수로 **이미 내려간** 공고까지
돌아보는 깃발입니다. 「확인 필요」 칸을 훑을 때만 손으로 붙입니다.
단, **날수 뚜껑(「…일 넘음」)으로 내린 것은 다시 안 올라옵니다** —
`alive_mark` 와 `alive_targets` 양쪽에서 막았습니다 (2026-10-12).
