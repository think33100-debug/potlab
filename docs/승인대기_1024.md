## ㉠ `칸되메우기` — headcount 를 **까닭이 적혀 있을 때만** 덮습니다

### 왜

지금 창구는 `headcount` 를 **null 일 때만** 채웁니다. 그래서 통합 공고에서
**다른 직군 인원**을 집은 틀린 숫자를 못 고칩니다 (하온어린이집이 그 꼴이었고,
세중님 승인으로 **손으로** 고쳤습니다 — `tools/모집인원_한건고치기.mjs`).

### 바꿀 한 자리 (전문)

```sql
--  지금 (칸되메우기 본문)
      headcount = case
        when (r ? 'headcount') and j.headcount is null
             and not ('headcount' = any(v_잠긴칸))
        then (r->>'headcount')::int else j.headcount end,

--  바꾼 뒤
      headcount = case
        when (r ? 'headcount') and not ('headcount' = any(v_잠긴칸))
             and (j.headcount is null
                  /* ★ 2026-10-24 세중님 — **까닭이 적혀 있을 때만** 덮습니다.
                     창구가 「통합 공고인가」를 스스로 가리지 않습니다 —
                     부르는 쪽이 `인원덮기까닭` 을 적어 보내야 덮습니다.
                     edited_fields(사람이 고친 칸)·admin_locked 는 그대로 건너뜁니다 */
                  or nullif(r->>'인원덮기까닭','') is not null)
        then (r->>'headcount')::int else j.headcount end,
```

```
ACL      전: {postgres=X/postgres,service_role=X/postgres} · secdef=true
         인수(p_rows jsonb)가 그대로라 `create or replace` 가 ACL 을 유지합니다 (지침 6-2).
         올린 뒤 **글자까지 같은지** 찍어 견줍니다
되돌림    ~/되돌림/칸되메우기_되돌리기_<날짜>.sql (지금 전문 그대로)
칸기록    `칸기록_after` 트리거가 headcount 의 옛값·새값을 남깁니다 (확인했습니다 —
         하온 건에 「headcount 2 → 1」 줄이 찍혔습니다)
```


## ㉡ `admin_jobs` 뷰에 **`뽑은값` 칸**

### 왜

관리자 공고 수정 화면에 **모집인원(숫자)** 칸을 넣었습니다 (2026-10-24 세중님 2번 ·
배포 끝). 그런데 세중님이 말씀하신 「**원문 그대로** 글꼴(○명·0명)도 보이게」가
반만 됩니다 — 그 글꼴은 `job_posts."뽑은값"->>'모집인원'` 에 있고
**`admin_jobs` 뷰에 그 칸이 없습니다.** 화면은 지금 `detail` 쪽만 보여 주고,
없으면 「(이 뷰에 없음)」이라고 적습니다.

### 바꿀 자리

```sql
-- admin_jobs 뷰의 select 목록에 한 칸 더합니다 (뷰는 is_admin() 으로 잠겨 있습니다)
   j."뽑은값"   as "뽑은값",
```

```
지금 권한   admin_jobs — authenticated 에게 select · 본문이 is_admin() 으로 막습니다
            (2026-10-24 회원 토큰으로 긁어 **0줄**인 것을 확인했습니다)
되돌림      ~/되돌림/admin_jobs_되돌리기_<날짜>.sql (지금 전문)
딸린 것     `web/lib/admin-jobs.ts` 의 AdminJob 타입에 `뽑은값` 한 줄 (화면은 이미
            그 값을 그릴 자리를 만들어 뒀습니다)
회원 화면    **안 바뀝니다** — 회원은 이 뷰를 못 봅니다
```

★ 글꼴을 **고치는** 것(저장)은 `뽑은값` 이 jsonb 라 창구가 필요합니다 —
  그건 이 승인에 넣지 않았습니다. 지금은 **보여 주기만** 하는 제안입니다.

## ㉣ [승인대기 · M5] `job_one` 에 **기관 불변 칸**을 붙이는 창구

세중님 M5 — 「회원 화면이 기관 표를 읽는 자리는 11/1~6 화면 작업 때. 그 전엔
**읽기 창구만 승인대기에 전문으로**」.

### 전문 (job_one 의 select 끝에 네 칸)

```sql
--  지금 job_one 은 job_posts_pub 만 읽습니다. 기관 표를 **왼쪽 이음**으로 붙입니다.
--  ★ 의심 건·확인 안 된 이름 묶음은 **안 줍니다** — 아래 `쓸만한가` 가 그 자리입니다.
create or replace function public.job_one(p_id text)
 returns table(... 지금 칸 그대로 ...,
               "기관주소" text, "기관전화" text, "기관홈페이지" text, "기관채용페이지" text)
...
    select  ... 지금 그대로 ...,
            case when 쓸만한가 then o."주소"       end,
            case when 쓸만한가 then o."전화"       end,
            case when 쓸만한가 then o."홈페이지"   end,
            case when 쓸만한가 then o."채용페이지" end
      from job_posts_pub j
      left join job_posts p on p.id = j.id
      left join 기관 o on o.기관번호 = p."기관번호"
      /* 쓸만한가 — ㉠ 번호로 붙은 것(HIRA:)이거나 ㉡ 사람이 확인한 것(확인한때)만 */
      cross join lateral (select (p."기관번호" like 'HIRA:%' or o."확인한때" is not null)
                            as 쓸만한가) k
     where j.id = p_id
```

```
왜 이 울타리   이름으로만 붙은 202건에는 **동명 기관을 한 묶음으로 본 것**이 섞여
              있습니다(의심 14~56묶음). 그대로 내보내면 **남의 병원 주소·전화**가
              회원 화면에 붙습니다 — 가장 나쁜 꼴입니다
ACL           인수(p_id text)가 그대로라 `create or replace` 가 ACL 을 유지합니다.
              **돌려주는 칸이 늘어나므로** `create or replace` 가 거부할 수 있습니다 —
              그때는 `drop function` + 다시 만들기이고, **전 ACL 을 찍어 글자까지**
              돌려놓습니다 (지침 6-2a — service_role 이 빠지지 않게)
되돌림         ~/되돌림/job_one_되돌리기_<날짜>.sql (지금 전문 41줄)
화면           11/1~6 에 「병원 뜯어보기」 칸에서 씁니다. 그 전에는 **아무도 안 읽습니다**
확인           올린 뒤 비로그인·회원으로 각각 불러 ㉠ 칸이 늘었나 ㉡ 의심 건은
              네 칸이 **전부 null** 인가 ㉢ 빠지는 칸 0
```

  안전합니다 (동결은 수집기·DB 함수라 이 창구도 10/31 전에 올리는 것이 낫다면 말씀해 주십시오).
