## 1. 진단 — **수집기가 빈 값으로 덮어 지웠습니다**

세중님이 짚으신 그대로였습니다.

### 증거

14:2x 에 떠 둔 스냅샷(HS3 409건)과 17:1x 를 견주니 **되메우기가 채운 모집인원
4건이 지워져** 있었습니다.

```
HS190712781 광주보훈병원     1 → (빔)
HS258328719 충주의료원       1 → (빔)
HS726356583 성남시의료원     1 → (빔)
HS882336163 경북대학교병원   1 → (빔)
```

네 건의 `updated_at` 이 **전부 똑같이 2026-10-18 08:04:44 UTC(17:04 KST)** —
**한 번의 수집기 바퀴**에서 덮인 것입니다.

★ `job_state_log` 는 **hold·hidden·직군·까닭만** 적고 모집인원은 안 적습니다.
스냅샷이 없었으면 **못 짚었습니다.**

### 뿌리 — `on conflict` 24칸 중 가드가 **2칸에만** 있었습니다

```
apply_to_time   when excluded.apply_to_time is null then j.apply_to_time   ← 있음
deadline_src                                                               ← 있음
headcount       **없음**  → HS3 는 모집인원을 못 뽑아 null 을 보냄 → **지워짐**
work_place      **없음**  → 이번엔 수집기가 값을 보내서 살았을 뿐 (운)
detail          **없음** + **통째 교체** → 되메우기가 넣은 칸이 사라질 자리
evidence        없음 (우리가 쓴 글이라 수집기 것이 맞습니다 — 그대로 둡니다)
뽑은값           **병합** + admin_locked 보호 + {} 면 유지 ← 이것만 제대로 되어 있었습니다
```

**그래서 마감시각만 올랐고(27.3 → 31.3%) 모집인원은 내려갔습니다.** 딱 들어맞습니다.

### 고친 것 (올렸습니다)

`supabase/migrations/2026_10_18_collect_put_빈값으로덮지않기.sql`

```
headcount    excluded 가 null 이면 기존 값 유지
work_place   nullif(excluded.work_place,'') 가 null 이면 기존 값 유지
             (빈 글자도 빈 값으로 봅니다 — 수집기가 '' 를 보내는 자리가 있습니다)
detail       통째 교체 → **병합** (「뽑은값」과 같은 꼴 + admin_locked 보호)
             같은 열쇠는 새 값이 이기고 **없는 열쇠만** 지킵니다
```

**일부러 안 바꾼 것** — `apply_to` · `title` · `org_name` · `job_group` 등
**수집기의 본값**. 거기서 null 은 「기관이 지웠다」는 뜻일 수 있고, 가드를 걸면
낡은 값이 영영 남습니다. **증거로 확인된 세 자리만** 고쳤습니다.

확인 — 전문을 받아 `diff` 로 **바뀐 줄 23줄**(세 자리 + 주석)만인 것을 보고 올렸습니다.
ACL 전후 같습니다(`{postgres=X/postgres,service_role=X/postgres}`).

★ 올리는 과정에서 제 실수 하나 — JS `replace` 의 `'$$'` 가 **달러 하나**를 뜻해
`$function$` 가 `$` 로 깨졌습니다. `cat -A` 로 보고 함수 치환으로 고쳤습니다.

## 2. 원문 링크 점검

세중님 결정으로 **상세 내용은 원문으로 가서** 보게 되었으니 링크가 정확해야 합니다.
도구 `tools/원문링크점검.mjs` (자기 점검 7가지).

판정은 **그 공고 제목 토막이 쪽에 있나** 로 합니다 — 정찰이 쓰는 방법입니다.

### 셈 (2026-10-18 17:21 KST · 66건)

```
회원 화면 주소 있는 공고 342건
  워크넷(work24.go.kr) 306건 → **표본 30건**  (한 호스트에 306번 줄줄이 때리지 않습니다)
  그밖 36건 → 전수
──────────────────────────────────────────
○ 그 공고 쪽                 53건
★ 쪽에 제목이 없습니다        10건
없어짐말 「게시물이 존재하지」  3건
→ **쓸 수 없는 링크 13/66 (20%)**
```

### 출처별

| 출처 | 수 | 꼴 |
|---|---|---|
| **WN · WN2** | 6 | `empDetailAuthView.do?wantedAuthNo=…` 가 열리는데 제목이 없음 |
| **ND2** | 3 | **「게시물이 존재하지」 — 공고가 내려갔는데 회원 화면에 보입니다** |
| HS | 2 | 한국병원 `Sub05_12.asp?…Srno=3561` · 청주의료원 `board.php?…wr_id=648` |
| AL | 1 | 대한적십자사 `redcross.or.kr/redrecruit/` — **목록 주소** |
| HS3 | 1 | 은평성모 `cmcep.or.kr/page/board/recruit/550021` |

마감일이 **미래**라 `hide_stale_posts` 가 못 내리고, 정찰은 **안 보고 있습니다.**

### 왜 정찰이 못 잡았나 — 정찰 범위를 셌습니다

```
출처   보이는공고  마지막본날   한번도안봄
```

**정찰은 HS3·AL2·HS·ND2 만 보고, 회원 화면 342건 중 306건(워크넷)은 한 번도 안 봅니다.**

워크넷은 **API 출처**라 매번 현재 목록을 받으니 정찰이 덜 필요할 수 있습니다
(`collect-worknet.mjs:17` — 「마감된 줄도 지우지 않습니다」). 그러나 **ND2 는
다릅니다** — 긁기 출처이고 3건 중 1건은 한 번도 안 봤습니다.

### 워크넷 6건은 **헛짚음일 수 있습니다** — 아직 안 가렸습니다

워크넷 상세 쪽이 **JS 로 내용을 불러오는 꼴**이면 제목이 HTML 에 없는 것이
당연하고, 링크는 멀쩡합니다. **쪽 하나를 받아 원문을 찍어 봐야** 갈립니다
(지침 2절). **아직 안 했습니다.**
