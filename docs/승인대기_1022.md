## A. `기관이름보정_아이디로` 를 비로그인에게서 걷기 (revoke)

**무엇** — 이 함수가 **비로그인(anon)에게 열려** 있습니다. 하루 요약 메일의
「허용 목록 밖에 열린 창구」에 뜹니다 (2026-10-19 에 만들 때 `grant … to anon` 을 넣었습니다).

**새는 자료는 없습니다** — `IMMUTABLE` 이고 **표를 한 줄도 안 봅니다.**
글자만 바꿔 돌려줍니다.

```sql
create or replace function 기관이름보정_아이디로(p_id text, p_기관 text, p_제목 text)
  returns text language sql immutable as $$
  select 기관이름보정(
    case when coalesce(p_id,'') ~ '^[0-9]+$' then 'AL2' else '그밖' end,
    p_기관, p_제목)
$$;
```

**영향 건수 — 0 건.** 부르는 자리를 전수로 찾았습니다.

```
저장소 전체 grep (web·app·tools·supabase·docs · node_modules 뺌)
  web/ · tools/ 에서 부르는 곳          0곳   ← REST 로 직접 부르지 않습니다
  부르는 곳은 job_one() · job_list() 둘뿐   (supabase/migrations/2026_10_19_화면도_보정이름_원문제목.sql)
```

둘 다 **SECURITY DEFINER** 입니다. 정의자 함수 안에서는 `current_user` 가
**임자(postgres)** 라 안쪽 함수의 EXECUTE 는 비로그인 권한으로 안 봅니다.

**이미 그렇게 돌고 있는 증거** — 이 함수가 부르는 `기관이름보정(text,text,text)` 은
`anon`·`authenticated` 에게서 **이미 걷혀 있습니다**(2026_10_19_기관이름보정_거느린곳.sql:58).
그런데도 비로그인 화면이 멀쩡합니다. 즉 **비로그인 권한은 쓰이지 않고 있습니다.**

### 돌릴 전문

```sql
-- tmp/보정함수_걷기.sql
begin;
revoke execute on function public."기관이름보정_아이디로"(text, text, text)
  from public, anon, authenticated;
grant  execute on function public."기관이름보정_아이디로"(text, text, text)
  to service_role;

-- 걷고 바로 확인합니다 — 비로그인 화면이 쓰는 두 창구가 멀쩡해야 합니다
select ("job_one"('306122') is not null) as job_one_멀쩡한가;
select proacl::text as acl_뒤 from pg_proc p join pg_namespace n on n.oid = p.pronamespace
 where n.nspname = 'public' and p.proname = '기관이름보정_아이디로';
commit;
```

### 되돌림

```sql
-- tmp/보정함수_걷기_되돌림.sql
grant execute on function public."기관이름보정_아이디로"(text, text, text)
  to anon, authenticated, service_role;
```

**ACL 전** `{postgres=X/postgres,anon=X/postgres,authenticated=X/postgres,service_role=X/postgres}`
**ACL 후(바라는 것)** `{postgres=X/postgres,service_role=X/postgres}`

★ 돌린 뒤 **비로그인 공고 상세 화면을 한 번 열어** 확인하고 결과를 보고에 적습니다.
  탈이 나면 되돌림 한 줄로 바로 돌립니다.

## B. 네숫자() ③ 의 「자격증 목록꼴」 그물을 넓히기

**무엇** — 오늘 넣은 ③ 의 목록꼴 그물이 **「중 1개 분야 이상」을 못 봅니다.**
서귀포시 공고가 그 꼴로 빠져나갔습니다 (직군 「작업치료사」로 회원 화면에 있었습니다).

```
지금 보는 말   「중 1개 이상」 · 「중 하나」 · 「각 2급 이상」 · 「관련 경력임을」
놓친 말        「다음 자격요건 중 **1개 분야 이상**의 자격(면허)를 취득한 사람
                1.간호사 2.사회복지사1급 3.**작업치료사** 4.임상심리사」  ← GJ305543
```

**영향 건수 — 지금 회원 화면에서 2건** (GJ305543 서귀포시 · GJ305988 충북경찰청).
둘 다 이미 손으로 보류함에 넣었습니다. 그물을 넓히면 **다음에 같은 꼴이 들어올 때
자동으로 ③ 에 잡힙니다** — 지금은 제가 눈으로 찾아야 합니다.

### 돌릴 전문 (네숫자() 안의 그 한 덩이만 바꿉니다)

```sql
-- 지금
            and "글".g ~ ('중[[:space:]]*1[[:space:]]*개[[:space:]]*이상|중[[:space:]]*하나'
                       || '|각[[:space:]]*2급[[:space:]]*이상|관련[[:space:]]*경력임을')
-- 바꿀 것
            and "글".g ~ ('중[[:space:]]*(하나|한[[:space:]]*가지)'
                       || '|중[[:space:]]*[0-9]+[[:space:]]*(개|가지)?[[:space:]]*(분야|종목|항목)?[[:space:]]*이상'
                       || '|각[[:space:]]*[0-9]+급[[:space:]]*이상'
                       || '|(어느|아래)[[:space:]]*하나'
                       || '|관련[[:space:]]*경력임을')
```

올릴 때는 `supabase/migrations/2026_10_22_네숫자_신뢰셋.sql` 을 그 자리만 고쳐
`create or replace` 로 다시 올립니다 (인수 같음 → **ACL 그대로**).
**되돌림** = 지금 올라가 있는 그 파일 그대로 다시 올리기.

★ 넓히면 「어느 하나」 같은 흔한 말 때문에 **멀쩡한 공고가 걸릴 수 있습니다.**
  올리기 전 마른 실행으로 전수를 세고(지금 2건), 늘어난 건을 하나씩 눈으로 봅니다.

## C. ✓ 돌렸습니다 — 네숫자() 의 CTE 를 `as materialized` 로

승인 자리지만 **함수가 터진 채였습니다.** 오늘 올린 신뢰 셋이
`statement timeout`(57014) 으로 죽어서 `네숫자()` 가 **아무 숫자도 못 냈습니다** —
아침 메일이 숫자 없이 나갈 자리였습니다. 승인받은 그 변경을 **돌아가게 만든 것**이라
멈추지 않고 고쳤습니다. 알려 드리고 결과를 적습니다.

```
까닭   PostgreSQL 12 부터 CTE 를 **줄마다 펼칩니다**(inline). 그래서
       `의심 as (select "직군의심"() as j)` 가 회원 공고 수(300)만큼 불렸습니다.
       직군의심() 한 번이 **0.8초** → 240초 → timeout.
고침   `의심 as materialized (select "직군의심"() as j)`  — 한 번만 부릅니다
확인   네숫자()->'신뢰셋' 이 다시 값을 냅니다 (① 0 · ② 0 · ③ 0)
ACL    인수 같음 → {postgres=X/postgres,service_role=X/postgres} 그대로
되돌림 supabase/migrations/2026_10_22_네숫자_신뢰셋_되돌림.sql
```
