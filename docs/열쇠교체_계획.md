## 왜 이 글이 있나

2026-10-11 에 제가 `.env.local` 을 셸로 `source` 했는데, 그 파일에
**이름 없이 값만 있는 줄**이 하나 있었습니다. 셸이 그 줄을 명령어로 읽어
`command not found` 와 함께 **값을 화면에 찍었습니다.**

- 찍힌 것 — **옛 `service_role` 열쇠** (지금 쓰는 것과 **다른 값**)
- 살아 있나 — **살아 있습니다.** 그 열쇠로 PostgREST 를 두드리니 **HTTP 200**
- 저장소에 샜나 — **아닙니다.** `git log --all -S` 0건 · `git grep` 0건 ·
  `.env.local` 은 `.gitignore:34` 에 있습니다. 샌 자리는 **그 대화 하나**입니다
- 한 것 — 그 떠돌이 줄을 `.env.local` 에서 뗐습니다

**세중님 결정 (2026-10-11) — 지금은 안 바꿉니다. 오픈 전이라 10/25 판정일에
처리합니다.** 이 글은 그날 쓸 지도입니다.

## 1. 좋은 길이 있습니다 — **새 API 키로 옮기고 옛 키만 끕니다**

공식 문서(`supabase.com/docs/guides/api/api-keys`)를 읽었습니다. **짐작이
아닙니다.** 문서가 말하는 것은 이렇습니다.

| | 옛 (legacy) | 새 |
|---|---|---|
| 꼴 | 긴 JWT (`eyJhbGciOi…`) | 짧은 글 (`sb_publishable_…` · `sb_secret_…`) |
| 브라우저에 두는 것 | `anon` | `sb_publishable_…` |
| 서버에만 두는 것 | `service_role` | `sb_secret_…` |
| 역할 | `anon` · `service_role` | **같습니다** — publishable → `anon`/`authenticated`, secret → `service_role` |
| RLS | service_role 이 건너뜀 | **secret 도 똑같이 건너뜁니다** (같은 `BYPASSRLS` 역할) |

문서에서 그대로 가져온 두 줄 —

> 「새 키를 만들어도 기존 `anon`·`service_role` 키는 **그대로 돕니다.**
> 대시보드 **Settings → API Keys** 에서 **끄는 것은 따로 하는 일**입니다.」

> 「**끄는 것은 되돌릴 수 있습니다** — 빠뜨린 데가 있으면 다시 켜면 됩니다.」

문서는 또 「`anon`·`service_role` 키를 **2026년 말까지 없앱니다**」라고
적고 있습니다. 어차피 한 번은 옮겨야 합니다.

### 그래서 권하는 길

```
① 새 키 둘을 만듭니다            옛 키는 그대로 돕니다 — 아무것도 안 멈춥니다
② 쓰는 데를 하나씩 새 키로 바꿉니다  한 군데씩. 멈춤 없음
③ 다 바꾼 뒤 옛 키를 **끕니다**     두 열쇠(지금 것 · 떠돌이 것)가 함께 죽습니다
④ 하루 지켜보고 괜찮으면 끝         빠진 데가 있으면 ③ 을 **되돌립니다**
```

**JWT 비밀을 통째로 바꾸는 것보다 훨씬 안전합니다** — 멈추는 시간이 없고,
되돌릴 수 있고, 한 군데씩 할 수 있습니다.

> **확인 못 한 것 하나** — 문서가 **저장소(Storage)** 와 **직접 서명한 JWT**
> 에 대해서는 말이 없습니다. 우리는 Storage 를 씁니다(`notices`·`proofs`·
> `ad-images`). ③ 전에 **Storage 올리기·내리기를 새 키로 한 번 해 봐야**
> 합니다. 「문서에 없으니 되겠지」로 넘기지 않습니다.

## 2. 안 되면 — JWT 비밀 교체. 바꿀 자리 목록

JWT 비밀을 바꾸면 **`anon` 까지 전부** 새로 받습니다. 아래를 **한꺼번에**
갈아야 하고, 그 사이 사이트와 수집기가 멈춥니다.

### 바꿀 자리

| 어디 | 무엇 | 몇 개 | 누가 |
|---|---|---|---|
| Supabase 대시보드 | JWT Secret 교체 | 1 | 세중님 |
| Vercel `potjob-web` | `NEXT_PUBLIC_SUPABASE_ANON_KEY` (production·preview·development **셋**) | 3 | 세중님 |
| GitHub Secrets | `SUPABASE_ANON_KEY` · `SUPABASE_SERVICE_KEY` | 2 | 세중님 |
| 서버 `~/potlab/.env` | `SUPABASE_ANON_KEY` · `SUPABASE_SERVICE_KEY` | 2 | 세중님 (값을 넣는 일이라) |
| 내 PC `.env.local` | `SUPABASE_SERVICE_KEY` | 1 | 세중님 |
| 앱(있다면) | 아직 없습니다 | 0 | — |

저장소 **코드는 안 고칩니다** — 전부 환경 변수에서 읽습니다. 센 것 (값이
아니라 **이름을 쓰는 파일 수**) —

```
SUPABASE_SERVICE_KEY 를 읽는 파일   26  (tools 23 · .github/workflows 2 · 그 밖 1)
SUPABASE_ANON_KEY   를 읽는 파일   35  (tools 31 · .github/workflows 4)
web 쪽                              web/lib/supabase.ts · supabase-server.ts ·
                                    supabase-browser.ts 세 벌 (Vercel 변수에서 읽습니다)
gas 쪽                              0 — 옛 시트는 다리를 거칩니다
```

GitHub Secrets 에 들어 있는 이름 전부 (열쇠 교체 때 함께 볼 것) —
`ALIO_DETAIL_KEY` `ALIO_LIST_KEY` `ALIVE_KEY` `APPS_SCRIPT_URL` `CLEANEYE_KEY`
`COLLECT_KEY_AL2` `COLLECT_KEY_CE2` `COLLECT_KEY_JF` `EXPORT_KEY` `OCR_GAS_URL`
`OCR_KEY` `PUSH_KEY` `SUPABASE_ANON_KEY` `SUPABASE_SERVICE_KEY` `SUPABASE_URL`
`VAPID_MAIL` `VAPID_PRIVATE` `VAPID_PUBLIC`

### 순서와 걸리는 시간 (JWT 비밀을 바꿀 때)

```
0. 크론을 멈춥니다 (서버 crontab 주석 · GitHub Actions 끄기)       5분
1. Supabase 에서 JWT Secret 교체                                  1분  ← 여기서부터 멈춥니다
2. 새 anon·service_role 을 받아 적어 둡니다                        2분
3. Vercel 변수 셋 → 다시 배포 (배포가 READY 될 때까지)             5분
4. GitHub Secrets 둘                                              3분
5. 서버 ~/potlab/.env 둘 → 수집기 하나를 손으로 돌려 확인          5분
6. 크론 다시 켜기 · 다리 한 바퀴 · 화면 한 번                      10분
                                                      멈추는 시간  약 15분
                                                      전체        30~40분
```

**로그인한 회원은 다시 로그인해야 합니다** — 가지고 있던 토큰이 그 비밀로
서명돼 있습니다. 오픈 뒤에 하면 회원이 전부 튕깁니다. **오픈 전에 끝내야
하는 까닭**입니다.
