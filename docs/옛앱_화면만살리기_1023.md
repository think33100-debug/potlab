# 옛 앱 — 「화면만 살리고 수집은 안 도는」 길이 있나 (2026-10-23 · `gas/` **읽기만**)

## ★★ 2026-10-23 — **할 필요 없어졌습니다. 모두의 창업 심사가 끝났습니다** (세중님)

  ```
  이 글은 「심사위원이 보는 화면을 살려야 하나」를 풀려고 쓴 것입니다.
  **심사가 끝났으니 그 걱정이 없어졌습니다.** 아래 길(ⓐ 스위치 · ⓑ 트리거 삭제)은
  **지금 할 일이 아닙니다** — 기록으로만 둡니다.

  그대로인 것 — `gas/` · `clasp push` · 옛 배포는 **손대지 않습니다** (CLAUDE.md 0절).
                심사가 끝났어도 제가 손댈 자리가 아닙니다. 세중님이 정하실 때까지 그대로입니다.
  ```

---

세중님이 읽기를 승인해 주셨습니다. **`clasp` 는 한 번도 안 돌렸고, 주소도 안 두드렸고,
`gas/` 파일을 한 자도 고치지 않았습니다.** 읽은 자리를 파일:줄로 적습니다.

## 한 줄 결론

**있습니다 — 그리고 스위치가 이미 코드에 있습니다.** `collect_cfg.on = false` 면
수집 트리거가 **첫 줄에서 돌아섭니다.** 다만 **순서가 중요합니다** — 승인을 먼저
풀면 수집이 30분 안에 다시 돕니다. **트리거를 먼저 끄고 그다음에 승인**입니다.

---

## 1. 「액세스 거부됨」이 승인 만료인가 — **그 꼴이 맞습니다** (코드가 그렇게 생겼습니다)

```
gas/appsscript.json
  "webapp": { "executeAs": "USER_DEPLOYING", "access": "ANYONE_ANONYMOUS" }
  "oauthScopes": [ …/auth/drive · …/auth/gmail.modify · …/auth/spreadsheets
                   …/auth/script.scriptapp · …/auth/script.external_request … ]
```

`executeAs: USER_DEPLOYING` 이라 **배포한 사람(주인 계정)의 승인으로** 돕니다.
그 승인이 풀리면 구글이 **선언 범위 가운데 가장 센 것**(`auth/drive`) 기준으로
거부 화면을 냅니다 — CLAUDE.md 8-4 에 적어 둔 그 화면입니다.

`access: ANYONE_ANONYMOUS` 라 **접근 설정 때문일 수는 없습니다**(비로그인 허용).
그리고 우리 코드가 「액세스 거부됨」이라는 글을 **내지 않습니다** —
`doGet` (gas/wage.js:268) 은 네 갈래뿐이고 전부 우리 화면으로 보냅니다:

```
gas/wage.js:271  q.callback → jsonp_(q)       다리·앱이 쓰는 자리
gas/wage.js:273  q.mail     → mailDo_(q)      보류 메일의 버리기/올리기
gas/wage.js:276  q.code|error → kakaoStray_   카카오가 잘못 온 것
gas/wage.js:279  q.admin === ADMIN_KEY → goHome_('/admin.html')
gas/wage.js:280  그 밖      → goHome_()       「POT JOB」 초록 안내 쪽 (284~)
```

**그러니 「액세스 거부됨」은 구글이 낸 글입니다.** 우리 코드에 그 글자가 없습니다
(`goHome_` 이 내는 글은 「POT JOB / 작업치료사와 물리치료사를 위한 가장 빠른 취업 정보」).

★ 다만 **「승인 만료다」를 제가 확인한 것은 아닙니다.** 코드 모양과
`job_sync_log` 10-11 07:22 의 글귀(「제목 「액세스 거부됨」」)가 그 꼴이라는 것까지입니다.
확인은 세중님이 시크릿 창으로 보고 계신 그것입니다.

## 2. healthCheck 를 돌리면 — **화면만 살아나지 않습니다. 수집도 함께 섭니다**

```
gas/wage.js:16999  function healthCheck() {
                     const sh = wsheet_();            ← 시트만 읽습니다
                     const rows = …getLastRow() …     ← 건수·셀 수를 로그로
                     return { rows, cells };
                   }
```

**함수 자체는 시트만 읽습니다.** 그런데 승인은 **함수 단위가 아닙니다** —
구글이 `appsscript.json` 의 **선언 범위를 한꺼번에** 묻고, 한 번 허용하면
`script.scriptapp`(트리거)·`script.external_request`(바깥 두드리기)까지 **다 풀립니다**
(CLAUDE.md 8-4 — 「구글이 선언 범위를 한꺼번에 물어 하나로 다 풀립니다」).

**트리거는 지워지지 않습니다 — 돌다가 실패했을 뿐입니다.** 그래서 승인이 풀리면
다음 차례에 **그대로 돕니다**:

```
gas/wage.js:16617  ScriptApp.newTrigger('collectTick').timeBased().everyMinutes(30)
gas/wage.js:8716   ScriptApp.newTrigger('hospTick').timeBased().everyHours(1)
gas/wage.js:9351   ScriptApp.newTrigger('mailInboxTick').timeBased().everyMinutes(5)
gas/wage.js:9147   ScriptApp.newTrigger('dropAnalyze').timeBased().atHour(9)·atHour(18)
```

→ **승인만 풀면 30분 안에 `collectTick` 이 돕니다.** 10-11 결정(옛 앱 수집 재개 안 함)과
어긋납니다.

## 3. ★ 그래서 길 — **두 가지. 둘 다 승인보다 먼저 합니다**

### ⓐ 수집 스위치를 끈다 — **코드에 이미 있습니다**

```
gas/wage.js:16418  function schedCfg_()
   PropertiesService.getScriptProperties().getProperty('collect_cfg')
   on: c.on !== false        ← **false 라고 적어야** 꺼집니다 (없으면 기본 켜짐)

gas/wage.js:16410  SCHED_DEFAULT = { on: true, fromHour: 7, toHour: 19, weekdayOnly: true, … }
```

그 스위치를 **보는 자리 둘** —

```
gas/wage.js:16457  collectTick_   if (!c.on) { Logger.log('수집이 꺼져 있습니다'); return 0; }
                   → 알리오·나라일터·워크넷·잡플렉스
gas/wage.js:8677   hospTick       if (!c.on) { Logger.log('수집이 꺼져 있습니다'); return 0; }
                   → 병원 홈페이지
```

**첫 줄에서 돌아섭니다.** 시트에 한 줄도 안 씁니다. 트리거는 돌지만 **아무 일도
안 합니다**(로그에 「수집이 꺼져 있습니다」만 남습니다).

끄는 창구 —

```
gas/wage.js:16583  function adminSaveSchedule(key, cfg)
                     adminAuth_(key) 를 지나야 하고, cfg.on 을 **false** 로 보냅니다
                     PropertiesService …setProperty('collect_cfg', JSON.stringify(save))
gas/wage.js:16566  function adminGetSchedule(key)   지금 값을 봅니다
gas/wage.js:4463   function showTriggers()          트리거 목록 + 「수집 설정(collect_cfg): 켜짐 …」
```

★ **그런데 이 길에는 닭-달걀이 있습니다.** `adminSaveSchedule` 을 부르려면 코드가
돌아야 하고, 승인이 풀린 채로 편집기에서 무엇을 돌리면 **그 순간 승인 창이 떠서
전부 풀립니다** — 그러면 수집도 같이 섭니다. 끄기까지 **30분 틈**이 생깁니다.

★★ **그리고 스위치를 안 보는 트리거가 둘 있습니다** —

```
gas/wage.js:9349  mailInboxTick   5분마다 · Gmail 의 「버리기/올리기」 메일을 읽어
                                  시트의 공고 상태를 바꿉니다. `c.on` 을 **안 봅니다**
gas/wage.js:9147  dropAnalyze     09시·18시 · 분석만 (시트를 읽습니다)
```

수집은 아니지만 `mailInboxTick` 은 **시트를 고칩니다.** 「수집은 안 돈다」를 지키려면
이 둘도 함께 봐야 합니다.

### ⓑ 트리거를 지운다 — **코드를 안 돌리고 사람이 합니다** ★ 제 추천

```
Apps Script 편집기 왼쪽 「트리거(시계 모양)」 화면에서 줄마다 ⋮ → 삭제
  코드를 돌리지 않으니 **승인 창이 안 뜹니다**
  화면(doGet)은 트리거와 **아무 관계가 없습니다** — 지워도 화면은 그대로입니다
그다음에 healthCheck 를 돌려 승인을 풀면 → **화면만 살아납니다**
되살리고 싶으면 setupJobTrigger() (gas/wage.js:16607) 한 번이면 다시 섭니다
```

**왜 ⓑ 가 나은가** — ⓐ 는 「풀렸다가 30분 안에 끄기」이고, ⓑ 는 「끄고 나서 풀기」입니다.
순서가 거꾸로입니다. 그리고 ⓑ 는 `mailInboxTick`·`dropAnalyze` 까지 한 화면에서
정리됩니다.

**왜 ⓐ 도 같이 적는가** — 트리거를 지우면 「무엇이 있었는지」가 사라집니다.
`showTriggers()` 의 출력을 **지우기 전에 한 번 찍어 두는 것**이 좋습니다
(그 함수도 코드 실행이라 승인 창이 뜹니다 — 그래서 **지우기 전 기록은 편집기
트리거 화면을 캡처**하는 쪽이 맞습니다).

## 4. 그래서 세중님께 드리는 순서 (확인 결과를 보고 함께 정하면 됩니다)

```
세중님 시크릿 창 결과가 「멀쩡하다」  → 할 일 없음. 승인은 안 풀려 있습니다
                                     (다리만 멈춘 것이고 화면은 따로 삽니다)
「액세스 거부됨」이 뜬다            → ① 편집기 트리거 화면을 **캡처**
                                     ② 트리거 **전부 삭제** (코드 실행 없음)
                                     ③ healthCheck 한 번 → 승인 (고급 → 허용)
                                     ④ 화면 다시 열어 확인
                                     ★ **새 배포를 만들지 마십시오** — 주소가 바뀌면
                                       .env.local 과 GitHub Secrets 양쪽을 고쳐야 합니다
```

★ 어느 쪽이든 **제가 할 일은 없습니다.** `clasp` 도 배포도 제 손이 닿지 않는
자리입니다 (CLAUDE.md 0절 · 2026-10-23 세중님 지시).
