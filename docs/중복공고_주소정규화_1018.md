# 중복 공고와 주소 정규화 (2026-10-18)

세중님 지시 **E**(「강진의료원 www 중복 + 주소 정규화 — 근본부터」)를 재어 본 것입니다.
**아직 아무것도 고치지 않았습니다.** 숫자와 까닭만 적습니다.

세어 보니 **강진의료원만의 일이 아니고, 서로 다른 세 가지가 섞여 있었습니다.**

---

## 0. 먼저 — 제가 처음에 잘못 센 것

첫 셈에서 「중복 39쌍 · 회원 화면에 보이는 것 **9건**」이라고 했습니다. **틀렸습니다.**

- `hidden = false and hold = false` 로만 셌습니다. 그런데 **`job_posts_pub` 는
  시험 자료(`시험병원 (마스터 전용)`)를 더 걸러 냅니다.** 그 6건이 「보임」으로
  잡혔습니다. `job_posts_pub` 로 다시 세니 시험 공고는 **회원 화면에 0건**입니다.
- **지침 8-14 가 경고한 바로 그 실수입니다** — 「회원 화면 줄 수를 `job_posts_pub`
  로 셉니다. `hidden=false` 만 보고 세면 보류함에 든 것까지 셉니다」.
  이번에는 보류함이 아니라 **시험 자료**였습니다.

**바로잡은 숫자 — 회원 화면에 보이는 중복은 6건입니다.**

---

## 1. 진짜 중복 — 주소와 제목이 **둘 다** 같은 것

```
14쌍 · 정리하면 18건 줄어듭니다 · 그중 회원 화면에 보이는 것 6건
```

강진의료원 7쌍이 여기 들어갑니다 (`www.gjmed.or.kr` ↔ `gjmed.or.kr`,
같은 `wr_id` — 515 · 513 · 504 · 503 · 498 · 493 · 492). 전부 숨김·보류입니다.

**제목이 살짝 바뀌어 두 번 담긴 것도 있습니다** — 이것은 **회원 화면에 보입니다**:

```
한림병원  recruit.hallym.net/job_posting/detail.php?mode=view&idx=495
  HS2141664325  「재활도수치료센터 작업치료사 모집 (경력무관)」   보임
  HS718447880   「재활도수치료센터 작업치료사 모집」              보임
  → 같은 글입니다. 기관이 제목에 「(경력무관)」을 더하자 **새 공고로 담겼습니다**
```

### 까닭

공고를 가리는 열쇠에 **주소가 그대로** 쓰입니다. 그래서
`www` 유무 · `http/https` · 제목 글자가 바뀌면 **다른 공고**가 됩니다.

### 고치는 길 (근본)

```
① 담을 때 주소를 정규화한다        소문자 · http(s):// 떼기 · 맨 앞 www. 떼기 ·
                                  끝 슬래시 통일 · 추적용 물음표 변수 빼기
② 공고 열쇠를 주소 **정규화 값**으로 만든다   제목을 열쇠에서 뺍니다
③ 이미 쌓인 18건은 합치거나 지운다   ★ 지우기는 승인 창이 뜹니다 (지침 8-7)
```

★ ②가 핵심입니다. ①만 하면 **앞으로 생길 것만** 막습니다.
★ 열쇠를 바꾸면 **이미 담긴 공고의 id 가 달라질 수 있습니다** — 찜(`job_stars`)·
  알림·조회 기록(`job_events`)이 id 를 들고 있습니다. **id 를 바꾸지 않고
  「같은 것으로 본다」만 더하는 쪽**이 안전합니다.

## 2. 더 심각한 것 — 주소가 **공고마다 다르지 않습니다**

주소는 같은데 제목이 여럿인 곳입니다. 중복이 아니라 **수집기가 공고별 상세
주소를 못 집고 있는 것**입니다.

| 주소 | 공고 수 | 제목 수 | 보임 |
|---|---|---|---|
| `andonghospital.co.kr/recruit/job/view.do?no=228` | **9** | 9 | 0 |
| `comwel.or.kr/recruit/hp/main.do` (근로복지공단) | **8** | 8 | 0 |
| `koddicpdd.fairyhr.com` (한국장애인개발원) | 5 | 5 | 0 |
| `redcross.or.kr/redrecruit/` (대한적십자사) | 4 | 4 | **1** |
| `dchp.or.kr/board/recruit/` (대청병원) | 3 | 3 | 0 |
| `nhimc.recruiter.co.kr/` (일산병원) | 3 | 3 | 0 |
| `hanhsp.co.kr/sub05/sub05_12.asp?…&srno=3560` | 2 | 2 | 0 |
| `gwhospital.co.kr/intro/recruit_view.php?idx=739` | 2 | 2 | 0 |

**왜 심각한가** — 회원이 공고를 열고 **「지원하러 가기」를 누르면 엉뚱한 공고나
목록으로 갑니다.** 안동병원 9건은 전부 `no=228` 한 공고를 가리킵니다.

다만 **지금 회원 화면에 보이는 것은 1건**(대한적십자사)뿐이라 당장 피해는 작습니다.

### 두 갈래로 갈립니다

```
㉮ 목록 주소를 그대로 쓰는 곳   comwel · redcross · koddicpdd · dchp · nhimc
                              → 설정의 `link` 규칙이 상세 주소를 못 집습니다.
                                사이트마다 봐야 합니다
㉯ 상세 주소를 **한 건만** 집는 곳  안동병원(no=228 9건) · hanhsp · gwhospital
                              → `link` 정규식이 **첫 번째 것만** 집어 모든 줄에
                                같은 주소를 붙이는 꼴로 보입니다. 이쪽은 설정
                                정규식 하나로 여러 곳이 같이 고쳐질 수 있습니다
```

㉯가 **먼저**입니다 — 같은 꼴이면 한 번에 고쳐집니다.
그리고 ㉯는 **「목록 줄마다 그 줄의 링크」를 집는지**를 보는 문제라
`tools/hosp/cfgs/*.json` 의 `row` 와 `link` 가 짝이 맞는지 봐야 합니다.

## 3. 세중님께 — 정할 것

```
① 열쇠를 바꿀지         주소 정규화 값으로 공고를 가립니다. **id 는 그대로 두고**
                       「같은 것으로 본다」만 더하는 쪽을 제안합니다
② 이미 쌓인 18건        합치기(한쪽을 숨김) vs 지우기(승인 창). **합치기를 제안합니다** —
                       찜·알림·조회 기록이 id 를 들고 있어 지우면 그것도 사라집니다
③ 한림병원 2건          회원 화면에 **지금 두 번 보입니다.** 한쪽(HS718447880 · 제목이
                       짧은 쪽)을 숨길지 — 승인하시면 바로 합니다
④ ㉯ 먼저인지           안동병원 꼴(상세 주소를 한 건만 집음)을 먼저 보는 것이 맞는지
```

## 4. 재는 법 (다시 재고 싶을 때)

```sql
-- 진짜 중복 (주소 정규화 + 제목이 둘 다 같음)
with n as (
  select id, title, hidden, hold,
         regexp_replace(regexp_replace(lower(url), '^https?://', ''), '^www\.', '') as 열쇠
    from job_posts where url is not null)
select count(*) as 쌍, sum(수)-count(*) as 남는것, sum(보임) as 그중보임 from (
  select 열쇠, title, count(*) as 수,
         count(*) filter (where not hidden and not hold) as 보임
    from n group by 열쇠, title having count(*) > 1) t;

-- 주소가 공고마다 다르지 않은 곳
with n as (
  select title, hidden, hold,
         regexp_replace(regexp_replace(lower(url), '^https?://', ''), '^www\.', '') as 열쇠
    from job_posts where url is not null)
select 열쇠, count(*) as 공고, count(distinct title) as 제목수,
       count(*) filter (where not hidden and not hold) as 보임
  from n group by 열쇠 having count(*) > 1 and count(distinct title) > 1
 order by 2 desc;
```

★ **「보임」은 `job_posts_pub` 로 다시 확인하십시오.** 위 셈의 `not hidden and
not hold` 는 시험 자료를 못 걸러 냅니다 (0절).
