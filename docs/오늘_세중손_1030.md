# 오늘 **세중님이 손으로** 하실 것 (2026-10-30 · 동결 뒤 첫 일)

`docs/개발환경_수지_1025.md` 와 `docs/24시간컴퓨터_준비.md` 에서 **세중님 손이 꼭 필요한
단계만** 뽑았습니다. 그 밖은 제가 다 준비해 두었습니다.

```
단계마다 적은 것   어디를 누르는지 · 넣을 값의 **이름** · 끝났는지 확인하는 법 · 걸리는 시간 어림
★ 값(열쇠·비번·주소)은 이 문서에 **한 줄도 없습니다.** 앞으로도 적지 않습니다 (지침 8-11)
★ 제게 열쇠를 주지 않으셔도 됩니다 — 아래 걸음은 다 **세중님 화면에서** 끝납니다
합계 어림        ① 개발용 환경 **35~40분** · ② 24시간 컴퓨터 **40분** · ③ 열쇠 자리 **10~15분**
순서 추천        ③ → ① → ②   (③ 이 수지 초대를 막고 있고, ① 이 11/1 화면 작업을 막습니다)
```

## ① 개발용 환경 (수지용) — 9단계 · **35~40분**

> 끝난 단계는 건너뛰십시오. **2번·7번이 끝나면 저에게 「2번 끝」·「7번 끝」 두 마디**만
> 주시면 제가 표본 공고를 넣고 Preview 를 확인합니다.

**1. Supabase 새 프로젝트** — `supabase.com` → 로그인 → **New project** (3분 + 생성 대기 2~3분)

```
누를 곳   New project → Organization 고르기 → 아래 칸 채우기
넣을 값   Name = potjob-dev   ·   Region = Northeast Asia (Seoul)   ·
         Database Password = **세중님만 아시는 값** (제게 주지 않으십니다 · 어딘가에 따로 보관)
확인법    프로젝트 화면 위 딱지가 「Setting up」 → **「Healthy」** 로 바뀌면 끝입니다
```

**2. URL·anon 열쇠 챙기기** — `Project Settings → API` (2분)

```
챙길 값의 이름   Project URL   ·   anon public (= 공개 열쇠)
손대지 않을 것   **service_role** 줄 — 복사하지도, 어디에 넣지도 않습니다
확인법          두 값이 손에 있으면 끝 (7번에서 Vercel 에 넣습니다 · 저에게는 안 주셔도 됩니다)
```

**3. 구조 올리기** — `SQL Editor` → **New query** → 파일 붙여넣기 → **Run** (5~10분)

```
붙일 파일   sql/기준구조_1030.sql   (오늘 뜬 것 · 27,836줄 · 1.0MB · **자료 0줄** · 비밀 글자 0)
확인법     Run 뒤 「Success」 · 왼쪽 **Table Editor** 에 표가 쭉 보이면 끝입니다
★ 1MB 라 한 번에 안 붙을 수 있습니다 — 「너무 크다」는 글이 뜨면 말씀만 주십시오.
  제가 **2~3조각으로 갈라** 드립니다 (갈라도 올리는 차례는 같습니다)
```

**4. 버킷 7개 만들기** — `Storage → New bucket` 을 일곱 번 (5분)

```
이름 (그대로)   notices · proofs · ad-images · avatars · posts · chat · home
공개 여부       **전부 Private** (공개로 만들면 5번 정책과 어긋납니다)
확인법         Storage 목록에 **7개**가 보이면 끝
```

**5. 저장소 정책 올리기** — `SQL Editor` → 붙여넣기 → **Run** (2분)

```
붙일 파일   sql/기준구조_storage정책_1025.sql   (우리 정책 23개)
확인법     Run 뒤 「Success」 · `Storage → Policies` 에 줄이 보이면 끝
★ 4번보다 **뒤**에 올립니다 (버킷이 없으면 정책이 붙을 자리가 없습니다)
```

**6. 숫자 맞춰 보기** — `SQL Editor` 에 아래 한 줄을 붙여 **Run** (1분 · **읽기만**)

```sql
select (select count(*) from pg_tables  where schemaname='public') as 표,
       (select count(*) from pg_views   where schemaname='public') as 뷰,
       (select count(*) from pg_policies where schemaname='public') as 정책,
       (select count(*) from pg_trigger where not tgisinternal)     as 트리거;
```

```
기다리는 값   표 **124** · 뷰 **11** · 정책 **91** · 트리거 **16** (운영과 같아야 합니다)
어긋나면      그 숫자를 알려 주십시오 — 3번이 중간에 끊긴 것입니다 (제가 어디서 끊겼는지 찾습니다)
```

**7. Vercel — Preview 에만 개발용 주소·열쇠** — `vercel.com → potjob-web → Settings →
Environment Variables` (5분)

```
새로 넣을 값의 이름   NEXT_PUBLIC_SUPABASE_URL      (값 = 2번의 Project URL)
                   NEXT_PUBLIC_SUPABASE_ANON_KEY (값 = 2번의 anon public)
Environments       **Preview 만** 켭니다 (Production·Development 는 끕니다)
손대지 않을 것       같은 이름의 **Production 줄** — 건드리면 운영 화면이 멈춥니다.
                   **service_role 은 Vercel 에 넣지 않습니다**
확인법             넣은 뒤 제가 `ui/*` 가지를 한 번 밀어 Preview 를 엽니다 —
                   공고 수가 **표본 수(50~100)** 로 보이면 개발용 DB 를 보는 것입니다
```

**8. Deployment Protection 확인** — `Settings → Deployment Protection` (3분)

```
볼 것    「Vercel Authentication」이 켜져 있나
켜져 있으면   **그대로 두고** 수지에게 **Share 링크**를 주십시오 (로그인 없이 그 링크만 열립니다)
플랜이 Share 를 안 주면   그때 보호를 끄고, **주소를 비공개로** 다룹니다 (아는 사람은 누구나 봅니다)
확인법   수지가 아닌 쪽(로그아웃한 브라우저)에서 그 링크가 열리면 끝
```

**9. Supabase 팀에 수지 초대** — `potjob-dev → Project Settings → Team → Invite` (2분)

```
권한    Developer   ·   **운영 프로젝트에는 초대하지 않습니다**
확인법   Team 목록에 수지 줄이 「Invited」 → 수지가 받으면 「Member」
```

> **GitHub 초대(협업자 Write + main 보호)는 ③ 뒤로 미뤘습니다** — 까닭은 ③절입니다.

## ② 24시간 컴퓨터 — 6단계 · **40분** (오늘 하실 거면)

```
옮기는 것    Claude Code 가 도는 **작업 자리**뿐입니다. 수집기·크론·DB 는 그대로 서버(potjob)
그래서      그 컴퓨터가 꺼져도 **공고 수집은 멈추지 않습니다**
```

**1. 깔기** (15분) — `Node 24.x` · `git` · `Claude Code` · ssh(윈도우 기본)

```
확인법   node -v → v24. · git --version · ssh -V · Claude Code 로그인 한 번
★ psql 은 **안 깝니다** — DB 는 서버에서만 두드립니다 (열쇠를 한 자리에 둡니다)
```

**2. 저장소 받기** (5분)

```
git clone https://github.com/think33100-debug/potlab
cd potlab && node tools/check.js
확인법   check.js 가 「통과」로 끝나면 준비된 것입니다 (gas/ 는 저장소에 없습니다 — 맞습니다)
```

**3. `.env.local` 값 넣기** — **세중님이 그 컴퓨터에서 직접** (5분)

```
적을 줄의 이름만   SUPABASE_URL= · SUPABASE_SERVICE_KEY= · APPS_SCRIPT_URL= · EXPORT_KEY=
값             세중님이 그 자리에서 넣습니다. 채팅·문서·커밋에 **안 적습니다** (지침 8-11)
확인법          node -e "console.log(require('fs').readFileSync('.env.local','utf8').split('\n').length)"
               → 줄 수만 찍힙니다 (값은 안 찍습니다)
★ `.env` 를 셸로 `source` 하지 않습니다 — node 가 읽습니다 (지침 8-12)
```

**4. 서버 열쇠** — **그 컴퓨터에서 새로 만들고 공개키만 서버에 붙입니다** (10분)

```
그 컴퓨터에서   ssh-keygen -t ed25519 -C "24시간컴퓨터"
서버에서       ~/.ssh/authorized_keys 에 그 **.pub(공개키)** 한 줄 붙이기  ← 세중님 손
~/.ssh/config  Host potjob / HostName … / User … / IdentityFile …   (주소는 여기 한 곳만 · 지침 8-5)
확인법        ssh potjob 'echo ok' → ok
★ 지금 열쇠를 복사하지 않습니다 — 복사하면 비밀키가 **두 자리**에 생깁니다
```

**5. 한 바퀴 확인** (5분)

```
① node tools/check.js                        어긋난 곳 없음
② node tools/쪽나눠받기_점검.mjs               걸림 0
③ ssh potjob 'cd ~/potlab && git pull --ff-only'   한 줄로 되는지
④ ssh potjob 'cd ~/potlab && node tools/작업나무점검.mjs'   ○ 깨끗합니다
⑤ 아침 메일 — **서버 크론**이 보냅니다. 컴퓨터와 무관합니다 (안 와도 이 걸음 탓이 아닙니다)
```

**6. 옛 자리 정리** (오늘 아니어도 됩니다)

```
옛 컴퓨터의 `.env.local` 을 지우실지는 세중님 자리입니다 — 지우면 열쇠가 한 자리로 줄어듭니다
서버에 파일을 넣는 길(scp·ssh cat 쓰기)은 **어느 컴퓨터에서도 안 씁니다** (지침 8-10)
```

## ③ ★ 열쇠 자리 하나 — **수지 GitHub 초대 전에** (10~15분)

세중님 말씀 둘을 두 문서에 대고 확인했습니다.

```
㉠ 「수지에게 운영 키 안 감」      → **두 문서 다 지킵니다** ○
   개발환경_수지_1025.md — 「운영 service_role·운영 DB 주소(SUPABASE_DB_URL)·서버 ssh 는
   어느 문서·대화·.env 예시에도 안 적습니다」(5절) · Preview 에만 개발용 값 ·
   「service_role 은 Vercel 에 넣지 않습니다」(3절) · 수지는 **개발용 Supabase 만**(Developer)
   24시간컴퓨터_준비.md — `.env.local` 은 **이름만** 적고 값은 세중님이 직접(3절) ·
   psql·DB 주소를 그 컴퓨터에 두지 않음 · 서버에는 **git pull·읽기만**(4절)

㉡ 「service_role 은 GitHub 에 없음」 → **이것은 지금 참이 아닙니다** ✗
   `.github/workflows/` 를 세어 보니 **`secrets.SUPABASE_SERVICE_KEY` 를 7개 워크플로가
   씁니다** (anon-check · collect-alio · collect-cleaneye · collect-jobflex · push ·
   signup-check · sync). 즉 운영 service_role 이 **GitHub Secrets 에 들어 있습니다.**
   ★ 값을 본 것이 아닙니다 — **이름이 쓰이는 자리**를 센 것입니다 (지침 8-11)
```

**왜 지금 걸리나** — 수지에게 **협업자 Write** 를 주면, 수지는 `ui/*` 가지에 파일을 밀 수
있습니다. 워크플로 파일도 파일입니다. `on: push` 로 도는 워크플로를 가지에 올리면 그
실행에서 **저 비밀값을 꺼내 볼 수 있습니다.** (지금 우리 워크플로는 `schedule`·
`workflow_dispatch`·`push: [main]` 뿐이라 **오늘 새는 길은 없습니다.** 수지가 들어오는
순간부터 생기는 길입니다.)

**고르실 길 둘** (제 추천은 ㉠)

```
㉠ 비밀값을 **환경(Environment)** 으로 옮기고 `main` 가지만 허용        10~15분 · 추천
   GitHub → Settings → Environments → New environment (이름 예: prod)
     → Deployment branches: **Selected branches = main** 만
     → Environment secrets 에 **이름 그대로** 다시 넣기
        (SUPABASE_URL · SUPABASE_SERVICE_KEY · SUPABASE_ANON_KEY · APPS_SCRIPT_URL ·
         EXPORT_KEY · ALIVE_KEY · OCR_KEY · OCR_GAS_URL · COLLECT_KEY_AL2 ·
         COLLECT_KEY_CE2 · COLLECT_KEY_JF · CLEANEYE_KEY · ALIO_LIST_KEY ·
         ALIO_DETAIL_KEY · VAPID_PUBLIC · VAPID_PRIVATE · VAPID_MAIL)
     → 저장소 비밀값(Repository secrets)에서는 **지웁니다**
   그 뒤 제가 워크플로 12개에 `environment: prod` 한 줄을 넣습니다 (`.github/` 는 수집기
   동결 자리가 아닙니다 — 그래도 **전문을 먼저 보여 드리고** 밀겠습니다)
   확인법   가지에서 아무 워크플로를 손으로 돌려 보면 비밀값이 **비어** 옵니다
            (크론은 `main` 에서 도니 그대로 돕니다)

㉡ 수지에게 **Write 를 주지 않고** 포크 + PR 로 받기                    0분
   포크에서 올라온 PR 은 비밀값을 **못 받습니다**(GitHub 기본). 화면 작업에는 충분합니다
   (수지는 자기 포크에서 `npm run dev` 로 보고, Preview 는 세중님이 가지를 밀 때 생깁니다)
   확인법   수지가 `main` 에도, 이 저장소 가지에도 밀 수 없는 것
```

```
★ 어느 쪽이든 **열쇠를 새로 발급할 필요는 없습니다** — 아직 샌 자리가 없습니다.
  (오픈 전 열쇠 재발급은 따로 적어 둔 자리가 있습니다 — 지침 8-11 의 WORK_KEY 줄)
★ 이 걸음은 **GitHub 설정**이라 제가 못 합니다. ㉠㉡ 어느 쪽인지 한 마디만 주십시오.
```
