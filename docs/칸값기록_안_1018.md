# 일곱 칸 값 기록 표 — 안 (2026-10-18)

세중님 지시 **5** — 「`job_state_log` 처럼 일곱 칸 바뀜(전→후·누가·언제)을 남기는 작은
기록 표. 오늘 같은 일을 스냅샷 없이 짚을 수 있게. **안(표 모양·쓰는 자리)만 먼저.**」

**아직 만들지 않았습니다.** 모양과 쓰는 자리만 적습니다.

---

## 0. 왜 — 오늘 스냅샷이 없었으면 못 짚었습니다

2026-10-18 에 되메우기가 채운 모집인원 4건이 지워졌습니다. 짚을 수 있었던 까닭은
제가 14:2x 에 **우연히** HS3 409건을 떠 두었기 때문입니다.

```
job_state_log 가 적는 것   hold · hidden · 직군 · 까닭   (옛_/새_ 둘 다)
적지 않는 것               모집인원 · 마감일 · 마감시각 · 근무지 · 지원자격 · 예상연봉 …
```

**칸 값은 아무 데도 안 남습니다.** `updated_at` 만 바뀌고 무엇이 어떻게 바뀌었는지는
사라집니다. 그래서 「언제 누가 지웠나」를 못 묻습니다.

---

## 1. 표 모양

```sql
create table public."칸기록" (
  id          bigserial primary key,
  job_id      text not null references job_posts(id) on delete cascade,
  칸          text not null,          -- 'headcount' · 'apply_to' · 'apply_to_time' ·
                                      -- 'work_place' · 'detail.지원자격' · 'detail.연봉' …
  옛값        text,                   -- 글자로 남깁니다 (칸마다 꼴이 달라서)
  새값        text,
  누가        text not null,          -- current_setting('app.누가') — 이미 쓰는 장치입니다
  왜          text,                   -- current_setting('app.왜')
  바뀐때      timestamptz not null default now()
);
create index on public."칸기록" (job_id, 바뀐때 desc);
create index on public."칸기록" (바뀐때 desc);
```

`job_state_log` 와 **같은 꼴**로 맞췄습니다 — `누가`·`왜`·`바뀐때` 이름까지
(지침 6절 — 두 벌로 만들지 않습니다). `app.누가` 는 `collect_put`·`밤정리`·
`admin_decide`·`칸되메우기` 가 **이미 `set_config` 로 넣고 있습니다.**

### 왜 값을 글자로 두나

칸마다 꼴이 다릅니다 — `headcount` 는 int, `apply_to` 는 date, `apply_to_time` 은
time, `work_place` 는 text, `detail.지원자격` 은 jsonb 속 글자. **한 표에 담으려면
글자가 가장 단순합니다.** 숫자로 다시 세어야 할 일이 생기면 그때 캐스트합니다.

## 2. 쓰는 자리 — **트리거 하나**가 맞습니다

### 왜 트리거인가

값을 바꾸는 자리가 여럿입니다 — `collect_put`(수집기) · `칸되메우기`(되메우기) ·
`admin_decide`(관리자) · 그리고 제가 오늘 한 **손 PATCH**. 자리마다 적게 하면
**한 자리를 빠뜨립니다** (오늘 제 PATCH 가 바로 그 자리였습니다).

```sql
create or replace function public."칸기록남기기"() returns trigger
language plpgsql security definer set search_path = public as $$
declare
  v_누가 text := coalesce(nullif(current_setting('app.누가', true), ''), '(모름)');
  v_왜   text := nullif(current_setting('app.왜', true), '');
begin
  /* 일곱 칸 중 **표의 칸**만. detail 속은 아래에서 따로 */
  if new.headcount is distinct from old.headcount then
    insert into "칸기록"(job_id, 칸, 옛값, 새값, 누가, 왜)
    values (new.id, 'headcount', old.headcount::text, new.headcount::text, v_누가, v_왜);
  end if;
  -- apply_to · apply_to_time · work_place 도 같은 꼴로
  /* detail 속 두 칸 — jsonb 라 ->> 로 꺼내 견줍니다 */
  if (old.detail->>'지원자격') is distinct from (new.detail->>'지원자격') then
    insert into "칸기록"(job_id, 칸, 옛값, 새값, 누가, 왜)
    values (new.id, 'detail.지원자격',
            left(old.detail->>'지원자격', 200), left(new.detail->>'지원자격', 200), v_누가, v_왜);
  end if;
  return new;
end $$;

create trigger "칸기록_before" before update on job_posts
  for each row execute function public."칸기록남기기"();
```

### ★ 트리거를 쓸 때 반드시 지킬 것 (지침 8-14)

```
2026-10-11 에 「새 공고만 보류함으로」 를 BEFORE INSERT 트리거로 했다가
upsert 에서 **기존 줄까지** 바뀌어 회원 화면이 358 → 80 이 됐습니다.
PostgreSQL 은 INSERT … ON CONFLICT DO UPDATE 에서 BEFORE INSERT 를 먼저 돌리고
`excluded` 는 **그 트리거가 고친 NEW** 입니다.
```

이 기록 트리거는 **`before update` 만** 걸고 **NEW 를 고치지 않습니다**(그냥
`return new`). 그래서 그 사고와는 다른 자리입니다. 그래도 올린 뒤
**`collect_put` 으로 한 바퀴 돌려 기존 줄이 안 바뀌는지** 봐야 합니다.

### 자리를 `after update` 로 할지 `before` 로 할지

`after update` 가 더 안전합니다 — NEW 를 못 고치니 사고가 날 수 없습니다.
다만 `after` 는 줄이 실제로 바뀐 뒤라 **`update` 가 되돌려지면 기록도 함께
되돌려집니다**(같은 트랜잭션). 그게 맞는 쪽입니다. → **`after update` 를 제안합니다.**

## 3. 얼마나 쌓이나 — 미리 재 봐야 합니다

```
회원 화면 342건 · job_posts 전체 수천 건
수집기가 하루에 도는 횟수 — 병원 16회(0 7-22) · 워크넷·알리오·클린아이 등
```

**빈 값 덮어쓰기를 고친 뒤**라 「바뀜」이 많이 줄 것입니다(전에는 채웠다 지웠다를
되풀이했습니다). 그래도 **하루 몇 줄이 쌓이는지 먼저 재고** 뚜껑을 정해야 합니다 —

```
㉠ 밤정리에서 **3개월 지난 것 지우기**  job_events 와 같은 규칙
㉡ 칸마다 **마지막 N 줄만** 두기
㉢ 먼저 아무 뚜껑 없이 켜고 **한 주 뒤 줄 수를 보고** 정하기  ← 제안
```

㉢이 맞아 보입니다 — 숫자를 모르고 뚜껑을 정하면 또 짐작입니다.

## 4. 쓰는 길 (무엇을 물을 수 있게 되나)

```sql
-- 「이 공고의 모집인원이 언제 누구에게 지워졌나」  ← 오늘 못 물었던 것
select 바뀐때, 옛값, 새값, 누가, 왜 from "칸기록"
 where job_id = 'HS726356583' and 칸 = 'headcount' order by 바뀐때 desc;

-- 「오늘 값이 **지워진** 칸」 (채운 것이 아니라 빈 것으로 바뀐 것)
select 칸, 누가, count(*) from "칸기록"
 where 바뀐때 >= current_date and 새값 is null and 옛값 is not null
 group by 1,2 order by 3 desc;
```

두 번째 것을 **하루 요약 메일에 한 줄**로 넣으면 오늘 같은 일이 **그날** 드러납니다.

## 5. 권한 (지침 6-2 · 6-3)

```sql
revoke all on table public."칸기록" from public, anon, authenticated;
grant select on table public."칸기록" to service_role;
revoke execute on function public."칸기록남기기"() from public, anon, authenticated;
```

★ `bigserial` 은 시퀀스를 만듭니다 — **`usage` 를 누가 가져야 하는지 같은
마이그레이션에서 정해야 합니다** (지침 8-13 의 `회원번호_seq` 사고). 넣는 것은
**트리거(definer)뿐**이라 회원·`authenticated` 에게는 줄 필요가 없습니다.
