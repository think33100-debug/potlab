## A. 「안 긁는 1층 기관」이 **우리가 긁는 곳 17곳을 세고 있습니다**

### 무엇을 찾았나

`일층병원_구멍()` 은 `hosp_sites.url` 이 비면 「못 긁는 줄」로 봅니다
(2026-10-19 에 그렇게 고쳤고 함수 주석에 까닭이 있습니다 —
「빛고을전남대·전북대가 그렇게 빠져 있었습니다 (공고 0건)」).

**그런데 주소가 빈 줄은 17곳이고 전부 API 로 읽는 꼴입니다.**

```
appsite  12곳   schmc 4곳   listjson 1곳     끈 줄(끔=true) **0곳**
그 꼴은 주소가 아니라 **호스트 + 번호**로 API 를 부릅니다 — 주소가 빌 수밖에 없습니다
```

그리고 **잘 들어오고 있습니다** —

```
부산대학교병원 23건 · 분당서울대학교병원 19 · 부민 9 · 용인세브란스 8 ·
아주대 7 · 길병원 7 · 전남대 5 · 순천향(서울·부천) 3·3 · 충북대 3 ·
삼육서울 2 · 서울 동부병원 2 · 순천향 천안 2 · 화순전남대 2 · 순천향 구미 1
0건은 **전북대 · 빛고을전남대 둘뿐**이고, 그 둘도 **긁고는 있습니다** —
우리 직군 공고가 없을 뿐입니다 (전북대는 오늘 밤 midas 로 6건을 읽었고
전문의·임상교수·레지던트·인턴·약사·간호직이었습니다)
```

즉 2026-10-19 의 고침이 **과했습니다.** 그 둘을 보고 「주소 없으면 사이트 아님」으로
바꿨더니, 주소가 필요 없는 열다섯 곳까지 사각지대로 세게 됐습니다.

### 영향 건수

```
지금          안 긁는 1층 기관 **459곳** / 대상 777곳
고치면        **442곳** (−17)
아침 메일 ①   그만큼 사실에 가까워집니다
회원 화면      **영향 없습니다** — 세는 숫자만 바뀝니다
```

### 전문

`supabase/migrations/2026_10_23_구멍_API꼴.sql` (함수 전문 · 바꾼 곳은 **한 군데**)

```sql
  ), 긁는곳 as (
    /* ★ 2026-10-22 밤 — **API 꼴은 주소가 없어도 긁는 곳입니다.** … */
    select s."이름열쇠" as k from hosp_sites s
     where (nullif(s.url, '') is not null
            or s.kind in ('appsite', 'schmc', 'listjson', 'cmc', 'greeting'))
       and not coalesce(s."끔", false)
```

바뀐 것은 `where` 한 줄뿐입니다 (앞은 `where nullif(s.url,'') is not null`).
끝에 `revoke … from public, anon, authenticated` + `grant … to service_role` 를
붙여 권한을 못 박았습니다 (지침 6-2).

```
ACL 전·후   {postgres=X/postgres,service_role=X/postgres} · prosecdef t  (인수 같음)
되돌림      supabase/migrations/2026_10_23_구멍_API꼴_되돌림.sql (지금 전문 그대로)
```

### 고르실 것

```
ⓐ 그대로 올립니다 — API 꼴을 「긁는 곳」으로 셉니다 (제 생각은 이쪽)
ⓑ 안 올립니다 — 그러면 아침 ① 이 459 로 남고, 그 안에 **우리가 잘 긁는 열다섯 곳**이
   섞여 있다는 것을 알고 보셔야 합니다
ⓒ `cmc·greeting` 은 빼고 `appsite·schmc·listjson` 만 넣습니다
   (지금 주소 빈 줄에 cmc·greeting 은 **없습니다** — 앞으로를 위해 넣어 둔 것입니다)
```

★ 이 고침은 **숫자를 줄이는 쪽**입니다. 숫자가 줄면 좋아 보이지만 **사실에 맞아야**
  의미가 있습니다 — 그래서 위에 곳마다 공고 건수를 적어 뒀습니다. 열다섯 곳은
  공고가 실제로 들어오고, 둘은 긁히지만 우리 직군 공고가 없는 곳입니다.
