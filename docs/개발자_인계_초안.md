## 1. 무엇을 만드는 곳인가

작업치료사·물리치료사 **채용공고를 하나도 안 빼고 모으는 곳**입니다.
많이 안 뽑는 기관이라도 하나 빠지면 「여기 오면 다 있다」가 무너집니다.

**1층(가장 중요한 곳)** — 공공기관 · 종합병원 · 대학병원.

커버리지는 느낌이 아니라 숫자로 말합니다 —
「대상 N곳 중 최근 30일 공고가 들어온 곳 M곳」.

자세한 것은 **`CLAUDE.md`** 를 먼저 읽어 주십시오. 그 파일이 이 저장소의 헌법입니다.

## 4. 반드시 읽을 규칙 — `CLAUDE.md`

실제로 밟은 실수를 적어 둔 파일입니다. **같은 자리를 또 밟지 않기 위한 것**이라
「일반론」이 아니고 전부 겪은 일입니다. 특히 이 여덟 절은 일을 시작하기 전에 읽어 주십시오.

| 절 | 무엇 |
|---|---|
| 1 | **원인을 확인하지 않고 고치지 않기.** 같은 증상을 두 번 못 고쳤으면 세 번째는 진단부터 |
| 3 | **주소·명세를 짐작으로 만들지 않기.** 하나 확인했다고 나머지를 규칙으로 만들지 않습니다 |
| 4 | **API 는 신청한 기능을 전부 확인하고 시작.** 「자동은 어렵다」 전에 안 쓰는 기능을 두드립니다 |
| 6 | **기준(날수·판정·조건)을 바꿀 때는 `grep` 으로 전부 찾아 함께 바꿉니다.** 찾은 곳 수를 보고에 적습니다 |
| 8-5 | 서버는 **이름으로만** 부릅니다 (`ssh potjob`). `known_hosts` 에서 주소를 집지 않습니다 |
| 8-7·8-8 | `delete`·`drop` 글자가 들어가면 Supabase 승인 창이 뜹니다. **거절된 SQL 은 창만 안 뜨게 고쳐서 다시 올리지 않습니다** |
| 8-10 | **서버 반영은 커밋 → `git pull` 로만.** `scp` 로 넣지 않습니다 |
| 10-3 | **기관의 성격(공공·대학·종별)을 이름으로 짐작하지 않습니다.** 심평원 공식 값만 씁니다 |

### 승인이 필요한 것은 셋뿐입니다

```
지우기          delete · drop · truncate
권한 바꾸기      grant · revoke · RLS 정책
회원 자료 고치기
```

나머지(새 표·새 칸·새 함수·새 화면)는 **전문을 대화에 남기고 바로 진행**합니다.
승인 창이 뜨는 SQL 은 **올리기 직전에 전문을 코드 블록으로** 적습니다.

**21시 이후에는 되돌릴 수 없는 작업을 하지 않습니다.**

## 6. 숨겨 둔 화면 — 아직 회원에게 안 보입니다

2026-10-09 에 만든 기능들입니다. **관리자·마스터에게만** 보이고,
회원에게는 「아직 준비 중이에요」 가 뜹니다.

| 주소 | 무엇 | 누구에게 보이나 |
|---|---|---|
| `/partner` | 담당자(채용·교육) 신청·증빙 올리기 | 관리자 · 마스터 |
| `/biz` | **채용 관리** — 공고 쓰기·고치기·마감·내리기 | 승인된 채용담당자 · 관리자 |
| `/edu/manage` | **교육 관리** — 과정·회차·신청자·답글 | 승인된 교육담당자 · 마스터 |
| `/talk` `/talk/<방>` | 1:1 대화 | 관리자 · 마스터 |
| `/verify` | 치료사 재직 인증 | 관리자 · 마스터 |
| `/alarm` · 탑바의 종 | 알림함 | 관리자 (마스터는 「관리자」 페르소나일 때) |
| `/master` | 마스터 로그인 · 페르소나 바꾸기 | 마스터 |
| `/admin/*` (22곳) | 관리자 화면 | 권한별 |

### 여는 법 — **하나씩** 엽니다

한꺼번에 열면 어디가 터졌는지 모릅니다. 화면마다 **한 줄**만 고치면 됩니다.

| 어디를 고치나 | 무엇을 | 열면 어떻게 되나 |
|---|---|---|
| 그 화면 맨 위 `if (!isAdmin && !마스터)` 갈래 | 지웁니다 | 회원에게 보입니다 |
| `components/alarm-bell.tsx` 의 `!isAdmin` | 지웁니다 | 모든 회원에게 종이 뜹니다 |
| `components/tab-bar.tsx` 의 `관리길()` | 그대로 둡니다 | 담당자 자격이 승인된 분에게만 뜨는 것이 맞습니다 |

**`/biz`·`/edu/manage` 는 이미 「승인된 담당자」 기준으로 돕니다** — 열고 말고가
아니라 **담당자를 승인하면 그분에게 보입니다.** 숨긴 것은 아직 승인된 담당자가
없기 때문입니다.

**막는 자리는 화면이 아니라 DB 입니다.** 화면에서 `isAdmin` 을 지워도
`교육담당자인가()` · `담당자공고쓰기()` 같은 창구가 그대로 거절합니다.
그래서 화면만 열어 보는 것은 안전합니다.

**페르소나 띠** — 마스터로 로그인하면 화면 아래에 빨간 띠가 뜨고,
역할을 바꿔 **회원이 겪는 것을 그대로** 볼 수 있습니다.
화면만 흉내 내는 것이 아니라 **DB 의 역할이 진짜로 바뀝니다** — RLS 까지 겪어 봅니다.
그래서 페르소나 중에는 관리자 힘이 꺼집니다 (`is_admin()` 이 false).

## 7-2. 캡처 스크립트 쓰는 법 — `tools/캡처.mjs`

**코드가 직접 찍습니다.** 비번을 손으로 치지 않고, 기록에도 안 남깁니다.

```
npm install -D playwright          (저장소 맨 위에서 · 한 번만)
npx playwright install chromium

node tools/캡처.mjs --목록          무엇을 찍는지만 봅니다 (140장)
node tools/캡처.mjs --손님만        로그인이 필요 없는 16장만
node tools/캡처.mjs                묶음 여덟 전부
node tools/캡처.mjs --묶음 관리자    한 묶음만
node tools/캡처.mjs --주소 http://localhost:3000
```

| 어떻게 | 왜 |
|---|---|
| 비번은 `.env` 의 `MASTER_EMAIL`·`MASTER_PW` 에서 읽습니다 | 파일에도 로그에도 값이 없습니다 |
| 로그인 칸은 **안 찍습니다** | 찍으면 메일 주소가 그림에 남습니다 |
| 틀리면 한 번만 시도하고 멈춥니다 | `/master` 가 다섯 번에 15분 잠급니다 |
| 페르소나는 **띠의 단추를 눌러** 바꿉니다 | 창구를 몰래 부르면 띠가 안 지나갑니다 |
| 끝나면 `finally` 에서 「관리자」로 되돌립니다 | 안 되돌리면 다음에 열 때 학생으로 들어가 있습니다 |
| 「비회원 보기」는 로그아웃 창과 **글자를 맞춰 봅니다** | 그림을 맞추면 빨간 띠 때문에 늘 다릅니다 |

**저장소 맨 위의 `package.json` 은 일부러 git 에 안 올립니다.** 서버에서
`git pull` 뒤 `npm install` 이 돌면 크로미움(수백 MB)까지 받으려 하기 때문입니다.
서버 크론이 쓰는 `web-push` 도 `--no-save` 로 따로 깔려 있습니다.

**배포 주소는 `potjob-web.vercel.app` 입니다.** `potjob.co.kr` 은 아직
**옛 앱(GitHub Pages)** 이라 거기로 찍으면 404 만 나옵니다
(2026-10-09 에 실제로 16장을 그렇게 찍었습니다).

## 8. 지금 승인을 기다리는 것

`docs/승인대기_1009.md` 에 일곱 줄이 있습니다. **각 줄에 무엇·왜·되돌리는 SQL·시험 방법**이 적혀 있습니다.

```
② 밤정리() 대화 보관 고치기        사진 30일 · 글 1년 · 신고 중이면 보존
③ 꺼 둔 열쇠 여섯 줄 치우기        2026-10-10 15:00 이후
④ 옛 훅 함수 치우기               한글 이름이라 훅 주소로 못 씁니다
⑥ 시험자료치우기() 실행           개발자가 화면을 다 본 뒤
⑦ storage 견본 여섯 장 · 시험 계정 셋   함수 밖이라 따로 지웁니다
```

①⑤ 는 끝났습니다.

**승인이 필요한 것은 셋뿐입니다** — 지우기(`delete`·`drop`·`truncate`) ·
권한 바꾸기(`grant`·`revoke`·RLS 정책) · 회원 자료 고치기.
새 표·새 칸·새 함수·새 화면은 **전문을 글로 남기고 바로 진행**합니다.

Supabase 승인 창은 **`delete` 글자만 있어도** 뜹니다 — 함수 본문이라 올릴 때
돌지도 않는 `delete` 도 마찬가지입니다. 그래서 지우는 함수는 **딴 파일로 뗍니다.**
거절된 SQL 은 **창만 안 뜨게 고쳐서 다시 올리지 않습니다** (작업지침 8-7·8-8).

## 9. 화면을 고친 뒤 할 것

```
1. npx tsc --noEmit                 (web/ 에서)
2. npm run lint                     새로 고친 파일에 지적이 없는지
3. node tools/check.js              API 표 ↔ METHODS 대조 · 중복 이름 · 색·조회 한도
4. 새 이름은 grep 으로 먼저 검색      중복 선언 방지
5. 화면↔창구 항목 이름 일치
6. 버전 올리기                       SERVER_VER · APP_VER
```

`node --check` 와 `tsc` 는 **실행 순서 문제를 못 잡습니다.**
시험이 통과했다고 「된다」가 아니라 「이 조건에서는 통과했다」입니다.
