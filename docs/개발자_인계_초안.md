## 1. 무엇을 만드는 곳인가

작업치료사·물리치료사 **채용공고를 하나도 안 빼고 모으는 곳**입니다.
많이 안 뽑는 기관이라도 하나 빠지면 「여기 오면 다 있다」가 무너집니다.

**1층(가장 중요한 곳)** — 공공기관 · 종합병원 · 대학병원.
재활·요양은 2층입니다. 사람이 많은 곳이 아니라 **정보가 귀한 곳**이 1층입니다
(재활병원에 작업치료사가 제일 많지만, 거기는 취업이 쉬워서 우리가 모아줄 값이 낮습니다).

커버리지는 느낌이 아니라 숫자로 말합니다 —
「대상 N곳 중 최근 30일 공고가 들어온 곳 M곳」.

자세한 것은 **`CLAUDE.md`** 를 먼저 읽어 주십시오. 그 파일이 이 저장소의 헌법입니다.

## 3. 열쇠와 접근 — 무엇을 받아야 일을 시작하나

| 받아야 하는 것 | 왜 | 주는 쪽 |
|---|---|---|
| GitHub 저장소 쓰기 권한 | — | 세중님 |

**받지 않는 것 (당장은)**

- **`service_role` 열쇠** — 서버 안에서만 씁니다. 브라우저 코드나 GitHub 에 절대 안 넣습니다
- **서버 ssh** — 수집기를 고칠 차례가 오면 그때
- **마스터 계정 비번** — 세중님 것입니다

**규칙 하나** — 열쇠 값은 **화면에 찍지 않습니다.** 로그에도, 커밋에도, 보고에도.
`git commit` 에 훅이 걸려 있어 열쇠 모양이 섞이면 막습니다
(커밋할 때 「○ 열쇠가 섞인 곳 없습니다」 가 뜹니다).

## 4. 반드시 읽을 규칙 — `CLAUDE.md`

실제로 밟은 실수를 적어 둔 파일입니다. **같은 자리를 또 밟지 않기 위한 것**이라
「일반론」이 아니고 전부 겪은 일입니다. 특히 이 여덟 절은 일을 시작하기 전에 읽어 주십시오.

| 절 | 무엇 |
|---|---|
| 1 | **원인을 확인하지 않고 고치지 않기.** 같은 증상을 두 번 못 고쳤으면 세 번째는 진단부터 |
| 3 | **주소·명세를 짐작으로 만들지 않기.** 하나 확인했다고 나머지를 규칙으로 만들지 않습니다 |
| 4 | **API 는 신청한 기능을 전부 확인하고 시작.** 「자동은 어렵다」 전에 안 쓰는 기능을 두드립니다 |
| 6 | **기준(날수·판정·조건)을 바꿀 때는 `grep` 으로 전부 찾아 함께 바꿉니다.** 찾은 곳 수를 보고에 적습니다 |
| 8-5 | 서버는 **이름으로만** 부릅니다 (`ssh potjob`). `known_hosts` 에서 주소를 집지 않습니다 |
| 8-7·8-8 | `delete`·`drop` 글자가 들어가면 Supabase 승인 창이 뜹니다. **거절된 SQL 은 창만 안 뜨게 고쳐서 다시 올리지 않습니다** |
| 8-10 | **서버 반영은 커밋 → `git pull` 로만.** `scp` 로 넣지 않습니다 |
| 10-3 | **기관의 성격(공공·대학·종별)을 이름으로 짐작하지 않습니다.** 심평원 공식 값만 씁니다 |

### 승인이 필요한 것은 셋뿐입니다

```
지우기          delete · drop · truncate
권한 바꾸기      grant · revoke · RLS 정책
회원 자료 고치기
```

나머지(새 표·새 칸·새 함수·새 화면)는 **전문을 대화에 남기고 바로 진행**합니다.
승인 창이 뜨는 SQL 은 **올리기 직전에 전문을 코드 블록으로** 적습니다.

**21시 이후에는 되돌릴 수 없는 작업을 하지 않습니다.**

## 5. 사람이 할 일과 코드가 할 일

이 프로젝트는 **전부 자동일 필요가 없습니다.** 안 되는 곳은
「손으로 확인할 곳」 목록에 넣고 마지막 확인일을 남깁니다.
**빠지지 않는 것이 자동화보다 중요합니다.**

| 코드가 하는 일 | 사람이 하는 일 |
|---|---|
| API 10곳에서 공고 긁기 | 못 가린 공고를 **보류함**에서 확인 후 올리기 |
| 제목·상세·첨부 PDF 에서 직군 찾기 | `.hwp` 중 못 읽은 것 |
| 마감일 읽기 | 마감일이 비면 「마감일 공고문 확인」으로 두고 눈으로 |
| 사업자번호 진위확인 (국세청 API) | 열쇠가 없으면 「수동 확인」 |
| 기관 성격(종별·설립구분) 심평원 값 채우기 | 공식 값이 비면 **미정으로 두고 관리자 확인** |

**짐작해서 채우지 않습니다.** 비면 비어 있는 대로 두고 화면은 안전한 쪽으로 적습니다.

## 6. 숨겨 둔 화면 — 아직 회원에게 안 보입니다

2026-10-09 에 만든 기능들입니다. **관리자·마스터에게만** 보이고,
회원에게는 「아직 준비 중이에요」 가 뜹니다.

| 주소 | 무엇 | 누구에게 보이나 |
|---|---|---|
| `/partner` | 담당자(채용·교육) 신청·증빙 올리기 | 관리자 · 마스터 |
| `/biz` | 승인된 담당자용 화면 | 승인된 담당자 · 관리자 |
| `/talk` `/talk/<방>` | 1:1 대화 | 관리자 · 마스터 |
| `/verify` | 치료사 재직 인증 | 관리자 · 마스터 |
| `/alarm` · 탑바의 종 | 알림함 | 관리자 (마스터는 「관리자」 페르소나일 때) |
| `/master` | 마스터 로그인 · 페르소나 바꾸기 | 마스터 |

**페르소나 띠** — 마스터로 로그인하면 화면 아래에 빨간 띠가 뜨고,
역할을 바꿔 **회원이 겪는 것을 그대로** 볼 수 있습니다.
화면만 흉내 내는 것이 아니라 **DB 의 역할이 진짜로 바뀝니다** — RLS 까지 겪어 봅니다.
그래서 페르소나 중에는 관리자 힘이 꺼집니다 (`is_admin()` 이 false).

## 9. 화면을 고친 뒤 할 것

```
1. npx tsc --noEmit                 (web/ 에서)
2. npm run lint                     새로 고친 파일에 지적이 없는지
3. node tools/check.js              API 표 ↔ METHODS 대조 · 중복 이름 · 색·조회 한도
4. 새 이름은 grep 으로 먼저 검색      중복 선언 방지
5. 화면↔창구 항목 이름 일치
6. 버전 올리기                       SERVER_VER · APP_VER
```

`node --check` 와 `tsc` 는 **실행 순서 문제를 못 잡습니다.**
시험이 통과했다고 「된다」가 아니라 「이 조건에서는 통과했다」입니다.
