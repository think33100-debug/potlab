# 관리자 화면 한 바퀴 — **코드와 DB 로만** 봤습니다 (2026-10-23)

세중님 지시 — 「버튼 실제 클릭·운영 DB 변경은 하지 말고 코드·흐름 점검과
안 되는 것 목록까지만」. **아무 단추도 안 눌렀고 DB 를 한 줄도 안 바꿨습니다.**
읽은 것만 적습니다 (`pg_policy`·`pg_constraint`·`pg_get_functiondef`·화면 코드).

---

## 1. 보류함 처리 — 세 단추가 **한 창구**로 모입니다

```
화면    web/app/admin/jobs/page.tsx:134  decide(id, what, jobGroup?, note?)
창구    rpc('admin_decide', { p_id, p_what, p_job_group, p_note })
본문    admin_decide(p_id text, p_what text, p_job_group text, p_note text)
       SECURITY DEFINER · 첫 줄이 **is_admin() 아니면 42501**
```

**받는 말이 넷으로 못 박혀 있습니다** — `살리기 · 숨기기 · 보류함으로 · 잠금풀기`.
그 밖은 `22023` 으로 막습니다. 아무 글자나 보낼 수 없습니다.

세 단추가 **같은 update 한 번**으로 끝납니다 —

```sql
hold   = (p_what = '보류함으로')
hidden = (p_what = '숨기기')
job_group = case when p_what = '살리기' then p_job_group else job_group end
hidden_why / hidden_on = 숨기기일 때만 적고, 아니면 **null 로 지웁니다**
admin_locked = (p_what <> '잠금풀기')      ← 결정하면 **잠깁니다**
admin_at = now() · admin_note = p_note · updated_at = now()
```

★ **이 꼴이 2026-09-29 에 고친 그 자리입니다** (화면 주석 116~133줄) — 전에는
`hold` 와 `hidden` 을 따로 뒤집어서 「보류 풀기」를 눌러도 `hidden` 이 남아
안 보였습니다(서귀포의료원 CE77568). 지금은 **셋 중 하나**라 그 꼴이 안 납니다.

### 「올린 공고가 규칙에 다시 내려가나」 — **안 내려갑니다**

```
admin_decide 가 admin_locked = true 를 켭니다 (잠금풀기만 false)
hide_stale_posts 의 다섯 갈래가 전부 `and not admin_locked` 입니다
  (2026_10_12_hide_stale_posts_날수뚜껑90.sql:67 · 73 · 84 · 92 · 99)
rejudge_hidden 에서도 뺍니다 — 숨기기가 아닐 때 delete 합니다
```

그래서 **관리자가 올린 공고는 매시 정리(05분)·재판정이 다시 못 덮습니다.**
규칙에 도로 맡기려면 **「잠금 풀기」** 를 누릅니다.

## 2. 공고 올리기 (= 「회원 화면에 올리기」) — **직군을 골라야 합니다**

```
단추가 보이는 조건   hold 이거나 hidden 일 때만 (page.tsx:303)
누르면              prompt 창 — 「1 물리치료사 · 2 작업치료사 · 3 공통(둘 다)」 (기본 3)
창구가 막는 것       살리기인데 직군이 셋 중 하나가 아니면 **22023** 으로 거절
```

★ **직군 없이 올릴 길이 없습니다** — 화면도 창구도 둘 다 막습니다. 「직군 빈칸인
채로 회원 화면에 올라가는 일」(보류함 새는 것에서 세는 그 값)이 **사람 손으로는
안 생깁니다.**

## 3. 숨김

```
단추가 보이는 조건   hidden 이 아닐 때
적히는 것           hidden_why = '관리자가 숨김' (+ 메모) · hidden_on = 한국 날짜
```

되살리는 길 — 「숨긴 것」 칸에서 그 공고의 **「회원 화면에 올리기」**.

## 4. 권한 — **표를 직접 지우는 단추가 하나 있습니다** (그래도 안전합니다)

```
[삭제] 단추만  browserSupabase().from('job_posts').delete().eq('id', id)   ← 창구가 아닙니다
권한          authenticated 에게 **DELETE** 가 있습니다 (SELECT·UPDATE 는 **없습니다**)
```

처음에는 이것이 구멍으로 보였습니다. **아닙니다** — RLS 가 켜져 있고 정책이 이렇습니다:

| 정책 | 무엇 | 역할 | 조건 |
|---|---|---|---|
| 공고 삭제는 관리자만 | DELETE | PUBLIC | `using = is_admin()` |
| 공고 수정은 관리자만 | UPDATE | PUBLIC | `using/check = is_admin()` |
| 공고는 누구나 읽습니다 | SELECT | PUBLIC | `(not hidden and not hold) or is_admin()` |

그래서 **관리자가 아니면 한 줄도 못 지웁니다.** 다만 **창구를 안 거치는 유일한
단추**라, 지워도 `칸기록`·`공고올림` 같은 기록이 **cascade 로 함께 사라집니다**
(아래 5-①).

## 5. ★ 안 되는 것 · 걸리는 것 — 넷

### ① [삭제] 는 **첨부가 있는 공고에서 실패합니다** (지금 1,214건)

```
공고첨부_공고id_fkey   삭제규칙 = 'a' (NO ACTION) — 막습니다
다른 자식은 전부 cascade  job_post_edits · job_stars · 공고신고 · 공고올림 · 칸기록
                        job_posts_같은공고_fkey 는 set null
첨부 줄이 있는 공고      **1,214건** → 그 공고의 [삭제] 는 FK 오류로 떨어집니다
```

화면은 `toast('지우지 못했어요 — ' + error.message)` 로 **Postgres 영문 메시지를
그대로** 보여 줍니다(`page.tsx:172`). 세중님께는 「공고첨부_공고id_fkey 위반」
같은 글이 보입니다 — **무슨 뜻인지 알 수 없는 글입니다** (지침 11절 — 화면에
진짜 이유가 뜨게).

**제 추천 — 고치지 않습니다.** 「보류함으로 보내는 쪽이 안전해요」가 이미
확인 창에 적혀 있고(168줄), 삭제는 **되돌릴 수 없습니다.** 동결 전에 손댈 값이
아닙니다. 오픈 뒤에 ⓐ 글귀를 한국말로 바꾸거나 ⓑ 첨부를 먼저 치우는 창구를
만들면 됩니다.

### ② 「회원 화면에 올리기」가 **브라우저 `prompt` 창**을 씁니다

```
page.tsx:149  const 답 = prompt(물음, '3');
```

돕니다. 다만 ⓐ 브라우저가 창을 막으면(설정·확장) 아무 일도 안 일어나고
ⓑ 휴대폰에서 줄바꿈이 깨져 읽기 어렵습니다. **동결 전에 바꿀 값은 아닙니다** —
화면 토막(11/1~)에서 단추 셋으로 펴면 됩니다.

### ③ 상태 칸의 **기본값이 「보류함」**입니다

`/admin/jobs` 를 그냥 열면 보류함만 보입니다(`page.tsx:36` — `|| 'hold'`).
**올라가 있는 공고를 찾으러 들어가면 「없다」로 보입니다.** 오늘 세중님이
GJ306151 을 찾으실 때 걸릴 자리입니다 → `?state=live&q=GJ306151` 로 가십시오
(`docs/관리자화면_들어가기.md` ③-1).

### ④ `admin_decide` 가 `updated_at` 을 **바꿉니다**

지침 9절은 「되메우기는 `updated_at` 을 바꾸지 않는다」입니다. 여기는
**되메우기가 아니라 사람의 결정**이라 바꾸는 것이 맞다고 봅니다 — 다만
`updated_at` 을 보고 도는 것이 생기면 그때 함께 봐야 합니다. **지금은 탈 없습니다**
(알림은 `db_insert_at` 을 봅니다).

## 6. 고칠 것이 DB 함수·ACL 인 것 — **없습니다**

넷 다 **화면 쪽**이거나 **고치지 않는 쪽이 맞는 것**입니다. 그래서
`docs/승인대기_1023.md` 에 올린 것이 없습니다.

```
① 첨부 FK     고치지 않습니다 (삭제는 되돌릴 수 없고, 보류함 길이 있습니다)
② prompt 창   화면 토막(11/1~)
③ 기본 칸     화면 토막 — 또는 주소로 가기 (지금 길이 있습니다)
④ updated_at  지금은 탈 없음 · 보고 도는 것이 생기면 다시
```

## 7. 아직 못 본 것 — **정직하게**

```
· 단추를 **실제로 눌러 본 적이 없습니다** (세중님 지시대로 안 눌렀습니다)
  → 「코드가 이렇다」까지이고 「눌러 보니 된다」가 아닙니다 (지침 15-2 ②)
· /admin/jobs/[id] 수정 화면은 이번에 **안 봤습니다** (한 바퀴의 다음 자리)
· AdminMerge(중복 짝 접기) · HoldCleanup(보류함 치우기) 도 안 봤습니다
```

세중님이 「보류함으로」를 누르실 때 **되는지 안 되는지가 그대로 한 번의 시험**이
됩니다 — 그 결과를 받아 이 글의 1절에 「눌러 보니 됐다」를 적겠습니다.
