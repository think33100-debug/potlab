## 2. 2099-12-31 의 뿌리는 **우리 코드가 아니라 병원 사이트**입니다

`grep` 으로 저장소 전체(`*.mjs` · `*.js` · `*.ts` · `*.sql` · `*.gs`)를 훑었습니다.
**자리채움 날짜를 넣는 코드가 한 줄도 없습니다.**

길병원 원문이 그렇게 적습니다 —

```
접수기간 2026.02.06(금) 08:00 ~ 2099.12.31(목) 00:00 D-26742
```

병원이 「채용시까지」 를 **2099.12.31 로 적는 것**입니다. 우리는 그대로 읽었습니다.
2099-12-31 인 4건 전부 HS·HS3(병원 긁기)이고, 알리오·클린아이가 준 값이 아닙니다.
(2026-12-31 쪽은 CLAUDE.md 15절에 적힌 클린아이 `PUB_END_DATE` 꼴입니다)

### 그래서 막는 자리가 다릅니다

「넣는 코드를 막기」가 아니라 **「읽을 때 안 믿기」** 입니다.

## 4. 출처가 없는 까닭 — `collect_put` 이 그 칸을 **안 받습니다**

`tools/collect-hosp.mjs:450` 주석에 이미 적혀 있었습니다.

> 「마감일을 어디서 얻었나 (2026-10-07). `job_posts.deadline_src` 칸이 있지만
> **`collect_put` 창구가 그 칸을 안 받습니다** — 창구를 고치는 대신 근거에 적습니다」

그래서 수집기는 `evidence.날짜출처` 에 적고, `deadline_src` 는 `alive_mark`

**지금은 마감일 2,086건 중 2,029건의 출처를 모릅니다.** 오늘 ① 판정에서
「틀린 값 5건」을 찾을 때도 「어디서 온 값인지」를 끝까지 못 밝혔습니다.

## 5. 제안 — 둘 다 **승인 뒤에** 올립니다

### ㉮ `collect_put` 이 `deadline_src` 를 받게 (2,029건의 뿌리)

```
지금  collect_put 의 insert 칸 목록에 deadline_src 가 없습니다
뒤에  r->>'deadline_src' 를 받아 담습니다. on conflict 쪽은
      **비어 있을 때만** 채웁니다 (출처를 덮지 않게)
수집기  collect-hosp.mjs 가 evidence.날짜출처 에 적는 것을 그대로 두고
        deadline_src 에도 같이 보냅니다 (한 줄)
        collect-nara·nid·cleaneye·worknet·alio 도 같은 자리에 한 줄씩
```

이것은 **앞으로 들어올 공고**를 고칩니다. 이미 담긴 2,029건은 그대로입니다 —
되메우기로 채울 수 있지만 원문을 다시 읽어야 하므로 ⑥ 칸되메우기 차례입니다.

### ㉯ 가짜 날짜를 **안 믿기** (7건 + 앞으로)

마감일 읽기는 `hs_dates.js` 와 DB 의 `deadline_from_title()` 두 자리에
있습니다. **둘 다** 같은 뚜껑을 겁니다 —

```
읽은 날짜가 **오늘 + 2년** 보다 뒤면 그 날짜를 **버립니다** (apply_to 를 비웁니다).
그러면 마감표시() 가 「채용시까지 · 공고문 확인」 으로 보여 줍니다 —
병원이 2099.12.31 로 적은 뜻이 바로 그것입니다.
```

2년으로 잡은 까닭 — 공공 공고는 「2026-12-31」 처럼 그해 말을 적는 일이
잦습니다(146건). 그것까지 버리면 멀쩡한 마감일을 잃습니다. **2년을 넘는 것은
사람이 적은 날짜가 아닙니다** (지금 7건 전부 2099 또는 그에 가깝습니다).

전문은 승인하시면 `⑥_마감일출처_받기.sql` 로 따로 드립니다 —
`collect_put` 은 수집기 여섯이 다 쓰는 창구라 **한 줄도 조심해서** 고쳐야 하고,
전후로 「담긴 줄 수가 같은지」를 확인해야 합니다.
