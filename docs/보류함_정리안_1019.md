**이 속도면 손으로는 못 따라갑니다.** 날마다 15건을 사람이 보려면 하루
30분이 듭니다. 개업 뒤에는 더 늘어납니다.

## 4. 일괄 처리 제안

### ㉠ **마감일이 이미 지난 162건 → 숨김** (가장 큼)

```
조건   hold and not hidden
       and apply_to is not null
       and (apply_to + coalesce(apply_to_time,'23:59')) at Asia/Seoul < now()
까닭   hidden_why = '마감 지남'
```

**손실이 없습니다** — 마감이 지났으니 사람이 봐서 올려도 회원 화면에
안 보입니다(`hide_stale_posts` 가 바로 다시 내립니다). 보류함에 두면
사람이 볼 것만 늘어납니다.

**408 → 246건.**

### ㉡ 고용24 직종코드 39건 → **코드표로 일괄 판정**

`detail.근거` 에 직종코드가 그대로 적혀 있습니다(231100 · 304000 …).
**우리 직군 코드가 무엇인지 한 번 정하면** 39건이 한꺼번에 갈립니다.
지금은 코드마다 1~10건씩 흩어져 있어 사람이 39번 같은 판단을 합니다.

★ 다만 **코드표를 아직 안 봤습니다.** 「231100 이 무엇인가」를 짐작하지
않습니다 (지침 3절) — 고용24 명세의 직종코드표를 받아 보고 정합니다.

### ㉢ HS 출처 36건 → **옛 출처라 그대로 숨김 제안**

전부 10-01~02 에 들어온 것이고 그 뒤 한 건도 없습니다. HS 는 10-03 에 끈
옛 수집기입니다. 같은 공고가 HS3 로 다시 들어왔다면 중복이고, 안 들어왔다면
원문이 없어진 것입니다. **`공고열쇠()` 로 HS3 쪽에 짝이 있는지 먼저 세어
보고** 제안하겠습니다 — 짝이 있으면 중복, 없으면 정찰에 맡깁니다.

### ㉣ 첨부가 아예 없는 270건 → **제목·본문으로 판정**

첨부가 없으면 더 읽을 것이 없습니다. 지금은 「첨부를 읽어야 함」 상태로
남아 영원히 기다립니다. **③ 칸뽑기 연결**(HS3 상세 본문 읽기)이 되면 이쪽이
크게 줄어듭니다 — 본문에서 직군·칸을 뽑을 수 있게 되기 때문입니다.

### ㉤ 첨부를 아직 못 읽은 34건 → **크론이 처리 중**

첨부 읽기 크론이 하루 300건까지 읽습니다. 오늘 아침 25건을 읽었고 못 읽은
것이 0 이었습니다. 이 34건은 차례를 기다리는 것이라 **건드리지 않습니다.**

```

㉣ 칸뽑기 연결 뒤 줄어들 것               -?   → ?
```

**㉠~㉢만 해도 408 → 171건**입니다. ㉣(칸뽑기 연결)이 되면 HS3 112건의
상당수가 자동으로 갈립니다.

★ **「근거 없음 223건」을 고치는 것이 가장 값집니다** — 왜 보류됐는지
적히면 다음부터 일괄 처리 갈래가 저절로 드러납니다.

## 6. 실행 순서 제안

```
① 마감 지남 162건 숨김            ← 지금 바로. 손실 없음. 승인만 주시면
② 보류 까닭 적기 고침 (223건의 뿌리)  ← 수집기 쪽. 다음에 안 생기게
③ HS 옛 출처 36건 짝 세기 → 제안
④ 고용24 직종코드표 받아 보기 → 제안
⑤ 칸뽑기 연결 (③ 승인 뒤) → HS3 112건이 줄어드는지 재기
```

**①만 승인해 주시면 408 → 246 이 됩니다.** 나머지는 숫자를 먼저 재서
다시 제안하겠습니다 — 짐작으로 일괄 처리하지 않습니다.
