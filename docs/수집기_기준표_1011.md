# 수집기 「끝」 기준표 — 2026-10-11 실측

세중님이 정한 일곱 기준으로 수집기를 하나씩 재 본 것입니다.
**숫자는 전부 이 날 DB 에서 센 값**이고, 어떤 질의로 셌는지 아래에 적었습니다.

○ 됨 · △ 반쯤 · × 안 됨

---

## 0. 먼저 — 「새 공고가 멈췄다」는 **공휴일이었습니다**

```
10-08 목  새 공고 52건
10-09 금  4건   ← 한글날
10-10 토  1건
10-11 일  6건   ← 전부 BIZ 시험 공고
```

근거 셋

```
① 공휴일 표      2026-10-09 「한글날」 (공공데이터 특일 API · 10-05 에 받음)
② 대조군        10-05 월도 「대체공휴일(개천절)」 → 그날도 4건.
                평일은 51~71건입니다
③ 날짜 창 없음   워크넷은 「접수 중인 공고 전부」를 받습니다 (callTp=L · occupation).
                regDt 로 자르는 자리가 없어 멈춘 창 때문이 아닙니다
```

**수집기 14개 하루 실패 0.** EDU 하나만 1회 — 칼텐본 외부 사이트 `HTTP 503`
(우리 쪽 탈이 아닙니다).

## 2. ③ 첨부 읽기가 전부 ×·△ 인 까닭 — **재료가 없습니다**

```
job_attachments            0줄
detail 안 첨부 주소 흔적     14개 출처 **전부 0건**
```

첨부를 여는 수집기는 넷(나라일터 · 클린아이 · 치매센터 · 알리오)인데,
**직군을 가리는 데만 쓰고 읽은 글과 주소를 버립니다.** 그래서 공고 상세
일곱 칸의 셋째 재료(「③ 첨부 공고문」)가 통째로 없습니다.

그리고 그 넷은 **kordoc 이 아니라 옛 `tools/hwp/`(맨손 UTF-16LE)** 를 씁니다 —
지침 8절이 「표를 못 가져온다」고 적은 그 모듈입니다.

**kordoc 은 서버에 깔려 있고 돕니다**
(`~/potlab/tools/kordoc/node_modules/kordoc/dist/cli.js`).
그런데 크론에 없고, **실제로 돌리는 파일이 하나뿐**입니다 —
`tools/kordoc/시험/읽기성능시험.mjs`(시험기).
`tools/공고칸채우기.mjs` 는 주석에 「PDF·HWP 는 kordoc」이라 적혀 있지만
`execFile`·`spawn` 이 **한 줄도 없습니다** — 첨부 **개수만 셉니다.**
(지침 6절 — 주석이 「되는 기능」처럼 보이는 자리)

### 고칠 것은 이미 준비돼 있습니다

갈래 `attach-prep` · 커밋 `e14de05` — 나라일터·알리오·클린아이가 공고문 주소를
`job_attachments` 에 담게 하는 것입니다. 승인대기 ⑪ 입니다.
**치우개 허용 목록이 2026-10-11 에 들어갔으니 막고 있던 조건이 풀렸습니다**
(합칠 때 `job_attachments` 를 치우개 `가리키는통` 에 더해야 합니다 — 안 더하면
담자마자 10분 뒤 지워집니다).

## 4. ① 직군이 낮은 까닭 — 쓰는 기능이 모자랍니다

**나라일터(GJ2)** — 신청한 6개 중 **셋만** 씁니다. 2026-09-08 에 지침 4절에
적어 둔 그 상태가 그대로입니다.

```

            ↑ 「검색 고유값에 해당하는 채용직급을 조회」 = 알리오 steps 와 같은 것
```

**상세 API(`callTp=D`)를 붙였기 때문**입니다. 붙이기 전 옛 WN 은 ① 68% · ② 9%
였습니다(표에 WN 줄로 남아 있습니다). **같은 일을 다른 출처에 하면 같이 올라갑니다.**

## 어떻게 셌나 (되재 볼 때 쓰십시오)

```sql
-- ② 일곱 칸 채움
with v as (
  select source,
    (headcount is not null or 뽑은값->>'모집인원' is not null) as 모집인원,
    (apply_to is not null) as 접수마감,
    (coalesce(work_place, 뽑은값->>'근무지') is not null) as 근무지,
    (coalesce(detail->>'지원자격', 뽑은값->>'지원자격') is not null) as 지원자격,
    (coalesce(detail->>'연봉', 뽑은값->>'예상연봉') is not null) as 예상연봉
  from job_posts
  where coalesce(hidden,false)=false and coalesce(시험자료,false)=false
    and collected_at > now() - interval '30 days')
select source, count(*),
  round(100.0*count(*) filter (where 모집인원)/count(*)), …
from v group by source;

-- ① 직군 채움 (보이는 것만)
select source, count(*),
  round(100.0*count(*) filter (where job_group is not null and job_group<>'')/count(*))
from job_posts
where coalesce(hidden,false)=false and coalesce(시험자료,false)=false
  and collected_at > now()-interval '30 days' group by source;

-- ⑦ 1층 커버리지 (org_targets 로 세야 합니다 · 기관 표는 돌고 돕니다)
with 긁힌곳 as (select distinct 견줄이름(org_name) k from job_posts
                where collected_at > now()-interval '30 days' and org_name is not null)
select 갈래, count(*), count(*) filter (where 견줄이름(name) in (select k from 긁힌곳))
from org_targets group by 갈래;

-- 0. 날별 새 공고 + 요일
select (db_insert_at at time zone 'Asia/Seoul')::date,
       to_char(db_insert_at at time zone 'Asia/Seoul','Dy'), count(*)
from job_posts where db_insert_at > now()-interval '25 days' group by 1,2 order by 1;
```

`db_insert_at` 이 빈 줄은 **0건**입니다 — 그래서 위 셈이 새 공고를 안 놓칩니다
(먼저 확인했습니다).
