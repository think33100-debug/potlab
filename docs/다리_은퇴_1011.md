## 2. 그런데 — **다리 말고도 옛 앱에 매달린 것이 둘 있습니다**

출처는 괜찮은데, 같은 Apps Script 에 **다른 것**이 걸려 있습니다.

| 무엇 | 어디 | 지금 | 옛 앱이 필요한가 |
|---|---|---|---|
| 다리 (시트 → `job_posts`) | `tools/sync_jobs.js` | **멈춤** (10-09 17:22 뒤로 기록 없음) | 은퇴 가능 |
| **푸시 알림** | `scripts/send-push.js` → `pushPending` | **멈춤** | **지금은 필요합니다** ← |
| OCR (그림 공고문 읽기) | `OCR_GAS_URL` | **멀쩡합니다 (HTTP 200)** | **다른 Apps Script 입니다** |

**OCR 은 별개 프로젝트라 멀쩡합니다.** 두드려 확인했습니다 —
`{"ok":true,"what":"potjob OCR","열쇠있음":true}`. 승인이 풀린 것은
`APPS_SCRIPT_URL` 쪽 하나뿐입니다.

### 푸시 알림이 문제입니다

`scripts/send-push.js` 가 **「보낼 것 있냐」를 Apps Script 에 묻습니다**
(`pushPending`). 지금 그 자리가 403 이라 **푸시가 하루 세 번 다 헛돕니다.**

그런데 **Supabase 에 이미 같은 창구가 있습니다** —
`보낼알림(p_secret, p_하루상한, p_몇개)` · `알림보낸것남기기()` ·
`알림기기등록()`. 즉 **옮기기만 하면 됩니다.**

**10/13 에 알림함을 여는 것이 첫 순서**인데(`docs/오픈점검_1101.md` 2절),
그 전에 이것을 옮겨야 알림이 실제로 갑니다.

## 3. 다리 은퇴 계획 (승인대기 ⑳)

### 멈추는 법

```
1. 푸시를 먼저 옮깁니다 — scripts/send-push.js 가 Apps Script 대신
   Supabase 창구(보낼알림)를 보게. **이게 끝나기 전에는 멈추지 않습니다**
2. .github/workflows/sync.yml 의 schedule 두 줄을 주석으로 막습니다
   (파일은 지우지 않습니다 — 되돌릴 때 주석만 풀면 됩니다)
3. 하루 지켜봅니다 — 보이는 공고 수가 줄지 않나
     select count(*) from job_posts where not hidden and not hold;
     (2026-10-11 17:40 기준 **363건**)
4. 일주일 지켜본 뒤 push.yml 도 같이 봅니다
```

### 남길 기록

- `job_sync_log` — **지우지 않습니다.** 다리가 무엇을 했는지 남은 유일한 기록
- `collector_state` — 다리가 쓰던 표. 그대로 둡니다
- 옛 이름 출처(`WN`·`HS`…)로 담긴 공고 697건 — 그대로 둡니다.
  **옛 시트가 우리가 가진 유일한 이력입니다**
- 구글 시트 자체 — 손대지 않습니다

### 되돌리는 법

```
1. Apps Script 편집기에서 healthCheck 한 번 실행 (승인 다시 받기)
2. sync.yml 의 schedule 주석을 풉니다
3. 손으로 한 바퀴 → job_sync_log 에 ok=true 가 남는지
```

**옛 앱을 영영 끄는 것이 아닙니다.** 시트와 Apps Script 는 그대로 두고
**다리만 멈춥니다.** 언제든 되살릴 수 있습니다.
