권한과 RLS

원칙

  • 표를 직접 안 읽습니다. 창구(security definer 함수)로만 드나듭니다
  • 화면의 isAdmin 은 단추를 보일지 말지에만 씁니다. 막는 자리는 DB 입니다
  • 숨긴 화면도 같습니다 — 화면에서 isAdmin 을 지워도 창구가 거절합니다

세 가지 함정 (실제로 밟았습니다)

① revoke … from anon 만으로는 아무것도 안 닫힙니다.

anon 은 PUBLIC 에 딸려 있습니다.


revoke execute on function f() from anon;           -- 안 닫힙니다
revoke execute on function f() from public, anon;   -- 닫힙니다
grant  execute on function f() to authenticated;

② 함수 인수를 바꾸면 그것은 새 함수입니다. PostgreSQL 이 새 함수를

PUBLIC 에게 EXECUTE 로 엽니다. 2026-09-25 에 org_public_host_branch 가

인수를 하나 더하면서 기관 58,610곳이 보름 동안 비로그인에게 열려 있었습니다.

③ 기본 권한을 닫아 두는 것은 여기서 안 됩니다.

alter default privileges … revoke execute on functions from public 을 걸고

시험해 봤더니 그대로 PUBLIC 이 붙었습니다. 마이그레이션마다 손으로 겁니다.

그래서 **새 함수를 만들 때는 같은 SQL 끝에 revoke … from public, anon 을

함께 넣습니다 — 트리거 함수도 예외가 아닙니다.**

절무엇
1원인을 확인하지 않고 고치지 않기. 같은 증상을 두 번 못 고쳤으면 세 번째는 진단부터
2진단 함수는 응답 원문 500~1,200자와 항목 이름 목록을 찍습니다
3주소·명세를 짐작으로 만들지 않기. 하나 확인했다고 나머지를 규칙으로 만들지 않습니다
4API 는 신청한 기능을 전부 확인하고 시작. 「자동은 어렵다」 전에 안 쓰는 기능을 두드립니다
5응답을 보고 코드를 씁니다. 받은 파일이 정말 그 형식인지 확인 (PDF 는 앞 5글자 %PDF-)
6기준을 바꿀 때는 grep 으로 전부 찾아 함께 바꿉니다. 찾은 곳 수를 보고에 적습니다
6-2 · 6-3인수를 바꾸면 새 함수 · revoke from anon 만으로는 안 닫힘
6-2b밖에서 이름으로 부르는 것은 영어로 (훅 주소 · URL 경로)
8-5서버는 이름으로만 부릅니다 (ssh potjob)
8-7 · 8-8delete·drop 글자가 승인 창을 띄웁니다. 거절된 SQL 은 창만 안 뜨게 고쳐서 다시 올리지 않습니다
8-9시험 자료를 실제 회원 계정에 넣지 않습니다
8-10서버 반영은 커밋 → git pull 로만

10-3기관 성격을 이름으로 짐작하지 않습니다
10-4수시 금지 = 기관 성격 AND 우리 직군
