8. 알려진 문제 — 개발자가 먼저 알아야 할 것

8-1. 수집기가 첨부 공고문을 저장하지 않습니다


job_attachments  0줄        (공고 377건 중 첨부가 담긴 것 0건)

공고 상세 일곱 칸은 제목 → 상세 API → 첨부 공고문 순으로 채웁니다.

셋째 단계의 재료가 지금 없습니다. 그래서 —

  • 상세 API 에 없는 칸은 그려지지 않습니다 (「공고에 없음」이라고 안 적습니다)
  • 보이는 공고 377건 중 374건에 빈 칸이 있습니다 (/admin/blanks 에서 봅니다)
  • tools/공고칸채우기.mjs(되메우기)는 지금 돌려도 얻을 것이 적습니다 —

첨부를 담는 일이 먼저입니다 (승인대기 ⑨ 가 ⑧ 뒤인 까닭)

이 일은 인계 뒤로 미뤘습니다 (2026-10-10 세중님 지시 — 인계가 1순위).

어디를 고쳐야 하나 — 저장소를 뒤져 확인했습니다. 담을 자리도, 창구도,

주소를 받아 오는 코드도 이미 있습니다. insert 한 줄만 없습니다.


표      job_attachments (job_id · kind · name · url · parsed_at)
        지금 0줄. 쓰는 코드는 tools/공고칸채우기.mjs 하나뿐이고 **읽기만** 합니다
        (`grep -rn job_attachments` → 코드 2곳 · 문서 8곳. 넣는 곳 0)

주소를 이미 받는 곳
  tools/collect-nara.mjs:320   첨부받기(idx) → { pdf, hwp }
                               부르는 곳 395 · 405 줄

  tools/collect-cleaneye.mjs   cleaneye-file.mjs 의 첨부받기(URL)

세 수집기 다 공고문을 열어 글자를 읽습니다 — 직군을 가리는 데 쓰려고요.

읽고 나서 주소를 버립니다. 그 자리에서 job_attachments 에 한 줄 넣으면

일곱 칸의 셋째 재료가 생깁니다.

주의 둘.

1. 나라일터 주소는 &amp; 를 안 풀면 HTML 오류 화면이 옵니다. 이미

온전히() 가 풀어 두었으니 그 값을 넣으십시오 (작업지침 5절).

2. 넣은 뒤에 tools/공고칸채우기.mjs 를 돌립니다 (승인대기 ⑨). 되메우기는

updated_at 을 바꾸지 않습니다 — 그걸 보고 도는 것이 있습니다

(작업지침 9절).
