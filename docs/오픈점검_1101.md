## 3. 기능마다 끝까지 — 페르소나 점검표

페르소나 아홉 — **비로그인 · 학생 · 작업치료사 · 물리치료사 · 채용담당자 ·
교육담당자 · 채용+교육담당자 · 가입중 · 비회원보기**.

「본다」가 아니라 **「끝까지 해 본다」**입니다. 올리는 기능은 **올려 봐야**
된 것입니다 (작업지침 6-2b).

### ① 알림함

| 할 것 | 어느 페르소나 | 되면 무엇이 보여야 |
|---|---|---|
| 공고를 찜한다 → 마감 3일 전 알림이 오나 | 작업치료사 | 알림함에 한 줄 · 종에 빨간 점 |
| 알림을 읽는다 | 작업치료사 | 빨간 점이 사라짐 |
| 알림함을 연다 | 비로그인 | 로그인 안내 (빈 화면 아님) |
| 푸시 허용을 거절한다 | 학생 | 화면이 안 깨지고 알림함은 그대로 돎 |

| 할 것 | 페르소나 | 되면 |

## 4. 오픈 전 보안 — **네 가지**

### 4-1. 수집기 창구가 **비로그인에게 열려 있습니다**

```
collect_put    anon=O · authenticated=O · service_role=O
collect_beat   anon=O · authenticated=O · service_role=O
판정남기기      anon=O · authenticated=X · service_role=O
```

`anon` 열쇠는 **브라우저에 내려가는 공개 값**입니다. 지금은 `p_secret`
하나로만 막고 있습니다. 비밀이 한 번 새면 **아무나 공고를 넣을 수 있습니다.**

**고치는 법** — 수집기는 서버에서만 돕니다. `service_role` 로 옮깁니다.

```sql
revoke execute on function public.collect_put(text, text, jsonb)  from public, anon, authenticated;
revoke execute on function public.collect_beat(text, text, jsonb) from public, anon, authenticated;
revoke execute on function public.판정남기기(text, text, jsonb)     from public, anon;
grant  execute on function public.collect_put(text, text, jsonb)  to service_role;
grant  execute on function public.collect_beat(text, text, jsonb) to service_role;
grant  execute on function public.판정남기기(text, text, jsonb)     to service_role;
```

**인수 꼴을 먼저 확인하고 돌립니다** (위 SQL 의 인수는 아직 안 맞춰 봤습니다).
그리고 **수집기 열넷이 `SUPABASE_ANON_KEY` 대신 `SUPABASE_SERVICE_KEY` 로
부르게** 함께 고쳐야 합니다 — 안 고치면 수집이 통째로 멈춥니다.
한 수집기에서 먼저 해 보고 나머지를 옮깁니다. `p_secret` 은 **그대로 둡니다**
(두 겹이 낫습니다).

### 4-2. 가짜 조회수를 못 막습니다

`web/app/api/hit/route.ts` 는 봇 이름과 `prefetch` 만 거릅니다.
**같은 사람인지 가리는 `day_key` 를 브라우저가 줍니다.** 번호를 매번 새로
지어 보내면 조회수가 끝없이 올라갑니다. 아이피 제한도 없습니다.

**고치는 법 (셋 중 둘만 해도 됩니다)**

- 아이피+공고별 **1분에 몇 번**으로 묶기 (`/api/biz` 에 넣은 것과 같은 꼴)
- `day_key` 를 서버가 정하기 — 아이피+날짜를 해시해서 **브라우저 말을 안 믿기**
- `page_hits` 에 `(day, kind, target, day_key)` **유일 제약**을 걸어 같은 날
  같은 사람은 한 번만 세기

**왜 오픈 전인가** — 조회수는 **광고 값을 매기는 근거**입니다 (CLAUDE.md
「재활·요양 공고에는 조회수를 남긴다. 나중에 값을 매길 근거가 된다」).
거짓 숫자로 값을 매기면 되돌릴 수 없습니다.

### 4-3. 승인대기에 남은 것

| 번호 | 무엇 | 오픈 전에 꼭? |
|---|---|---|
| ② | `밤정리()` 대화 보관 고치기 | 1:1 대화를 열면 **필요합니다** |
| ③ | 꺼 둔 열쇠 여섯 줄 치우기 | 하면 좋습니다 |
| ④ | 옛 훅 함수 `hook_이메일가입막기` 치우기 | 하면 좋습니다 (`drop` 이라 승인 창) |
| ⑥⑦⑩ | 시험 자료 치우기 | **꼭** (5절) |
| ⑨ | `공고칸채우기` 실행 | 아니요 — ⑭ 로 거의 대신했습니다 |
| ⑪ | 수집기 첨부 담기 (`attach-prep` 합치기) | 「공고문에서 읽기」를 쓰려면 필요합니다 |

```
3. ⑥ 시험자료치우기() 실행 — 승인 창이 뜹니다
4. 센 뒤 확인 —
     select count(*) from job_posts where source = 'TEST';          → 0
     select count(*) from profiles where nickname like '시험%';      → 0
     저장소 proofs · notices 버킷 줄 수                              → 0
5. 화면 한 바퀴 — 관리자 회원 목록 · 공고 목록 · 커뮤니티
6. **캡처를 다시 찍습니다** — 지금 캡처 230장에 시험 계정이 들어 있습니다
```

**치운 뒤에는 시험 계정이 없습니다.** 11/1 뒤에 다시 시험해야 하면
**그때 새로 만들고 그 자리에서 치웁니다** (작업지침 8-9).
