2026-10-09 · **설계안입니다. 아직 하나도 안 만들었습니다.** 세중님 확인 뒤에 만듭니다.
이 문서의 SQL 은 모양을 보이려고 적은 것이고, 실제 마이그레이션은 확인 뒤에 따로 적습니다.

## 0. 한 장 요약

**새로 만드는 표 — 13개.** 기존 표는 **하나도 안 지웁니다.**

권한      권한, 권한기록                                    2
역할      회원자격, 마스터페르소나                            2
교육      교육과정, 교육회차, 교육신청, 교육리뷰, 교육리뷰답글    5

**고치는 함수 — 1개.** `is_admin()` 한 줄만 고치면 **90곳이 따라옵니다.**

**안 만드는 것** — 문구 표(기존 `home_texts` 를 씁니다) · 감사 로그 표(기존
`개인정보접속기록`·`job_post_edits`·`job_state_log` 를 씁니다) · 대화 표(이미 셋 다
있습니다).

## 2. 권한

### 2-1. 생각

지금은 `admins` 에 줄이 있으면 **90곳이 전부 열립니다.** 직원에게 「공고만 고치게」
주려면 그 90곳을 다 고쳐야 할 것 같지만, 그러지 않습니다.

```
is_admin()      「운영진인가」 — 관리자 화면에 들어올 수 있나. 90곳 그대로 둡니다
권한있나('코드')  「이 일을 해도 되나」 — 민감한 행동에만 덧붙입니다
```

**덧붙이는 것이지 바꾸는 것이 아닙니다.** 직원이 한 명도 없는 동안에는 `admins` 에
대표 한 명뿐이라 **동작이 하나도 안 바뀝니다.**

### 2-2. 표

```sql
-- 운영진 명단 (기존 표에 칸만 더합니다)
alter table admins
  add column 갈래   text not null default '대표'  check (갈래 in ('대표','직원')),
  add column 끈사람 uuid,
  add column 끈때   timestamptz;

-- 누가 무엇을 할 수 있나
create table 권한 (
  profile_id uuid    not null references profiles(id) on delete cascade,
  권한코드    text    not null,
  준사람      uuid    not null,
  준때        timestamptz not null default now(),
  primary key (profile_id, 권한코드)
);

-- 주고 거둔 기록 (지우지 않습니다)
create table 권한기록 (
  id        bigserial primary key,
  누구에게   uuid not null,
  권한코드   text not null,
  준것인가   boolean not null,        -- true 주기 · false 회수
  누가      uuid not null,
  언제      timestamptz not null default now(),
  까닭      text
);
```

### 2-3. 권한 목록 — 11개

| 권한코드 | 무엇을 | 지금 그 일을 하는 자리 |
|---|---|---|
| `공고관리` | 공고 수정·숨기기·삭제 | `admin_jobs` 뷰 · `job_posts` 규칙 3개 · `admin_공고내리기` · `admin_공고올리기` |
| `보류함` | 보류함 처리 | `admin_decide` · `보류함마감정리` · `admin_제목확인` |
| `통계` | 통계 보기 | `admin_stats_now`·`_daily`·`_screens`·`_devices`·`_top_jobs`·`_top_posts` |
| `회원관리` | 회원 관리 | `admin_회원목록` · `admin_회원정보보기` · `admin_회원표` · `admin_탈퇴이름` |
| `신고처리` | 커뮤니티·공고 신고 처리 | `admin_신고목록`·`admin_신고처리`·`admin_공고신고목록`·`admin_공고신고처리`·`hide_post` |
| `리뷰삭제` | 교육 리뷰 삭제 | (새로 만듭니다) |
| `기관승인` | 채용·교육 담당자 승인, 인증 자료 열람 | (새로 만듭니다) |
| `광고` | 광고 배너 관리 | `admin_광고배너` · `admin_광고배너고치기` |
| `문구` | 문구 수정 | `home_texts` 규칙 · `home_blocks` 규칙 · `ui_icons` 규칙 3개 |
| `운영진글` | 운영진 글 모아보기·삭제 | (새로 만듭니다) |
| `페르소나` | 모든 화면 보기 (역할 바꿔 보기) | (새로 만듭니다 · 마스터 계정만) |

**대표(세중님)만** 직원을 더하고 권한을 주고 거둡니다. 화면이 아니라 **RPC 안에서**
확인합니다 — 브라우저에서 `true` 로 만들어도 서버가 안 해 줍니다.

```sql
create function 권한있나(p_코드 text) returns boolean
language sql stable security definer set search_path to 'public' as $$
  select exists (select 1 from admins where profile_id = auth.uid() and 갈래 = '대표')
      or exists (select 1 from 권한  where profile_id = auth.uid() and 권한코드 = p_코드)
$$;
```

### 2-4. 어디에 덧붙이나

위 표의 「지금 그 일을 하는 자리」가 그대로 할 일 목록입니다. **55개 함수 중
28개**에 `권한있나(...)` 한 줄이 들어갑니다. 나머지(수집기 상태 보기·대조표 같은
읽기 전용)는 `is_admin()` 만으로 둡니다.

## 3. 역할

### 3-1. 생각

지금 `profiles.role` 은 `'현직' | '학생'` 두 값입니다(4명). 여기에 담당자를 섞으면
문제가 생깁니다 — **개인 강사는 치료사이면서 교육 담당자**입니다. 한 칸으로는 못
담습니다.

```
profiles.role      「이 사람이 누구인가」 한 가지만. 화면 기본 모양을 정합니다
회원자격            「무엇을 더 할 수 있나」 여러 줄. 메뉴를 더 보여줍니다
```

`role` 에는 `'채용담당자'` 만 더합니다 — 채용 담당자는 치료사 화면을 안 씁니다.
**교육 담당자는 `role` 을 안 바꾸고 `회원자격` 한 줄로 붙입니다.** 그래야 현직
치료사가 강사를 겸할 수 있습니다.

이렇게 하면 `channelsFor(role)`(`lib/channels.ts`)와 `/me` 가 **안 깨집니다.**

### 3-2. 표

```sql
alter table profiles
  add column 소속기관번호 bigint references 기관(기관번호);   -- 채용 담당자만

create table 회원자격 (
  id        bigserial primary key,
  profile_id uuid not null references profiles(id) on delete cascade,
  갈래       text not null check (갈래 in ('채용담당자','교육담당자기관','교육담당자개인')),
  소속       text,                     -- 기관(교육기관.이름) · 개인 강사면 null
  상태       text not null default '심사중'
             check (상태 in ('심사중','승인','반려','정지')),
  신청때     timestamptz not null default now(),
  정한사람   uuid,
  정한때     timestamptz,
  반려까닭   text,
  unique (profile_id, 갈래, 소속)
);
```

### 3-3. 여섯 역할이 화면에서 어떻게 갈리나

| 역할 | `role` | `회원자격` | 보이는 것 |
|---|---|---|---|
| 학생 | `학생` | — | 지금 그대로 |
| 작업치료사 | `현직` + `job_group='작업치료사'` | — | 지금 그대로 |
| 물리치료사 | `현직` + `job_group='물리치료사'` | — | 지금 그대로 |
| 채용 담당자 | `채용담당자` | `채용담당자`(승인) | 내 공고 관리 · 성과 · 우리 병원 |
| 교육 담당자(기관) | 바꾸지 않음 | `교육담당자기관`(승인) | 교육 올리기 · 신청자 관리 |
| 교육 담당자(개인) | 바꾸지 않음 | `교육담당자개인`(승인) | 위와 같음 + 「면허 확인 강사」 배지(선택) |

## 4. 마스터 페르소나

### 4-1. 생각

**「서버 권한도 진짜 적용」** 이 핵심입니다. 화면만 바꿔 보여주면 RLS 를 못 시험하고,
앱스토어 심사에서도 가짜가 드러납니다. 그래서 전환할 때 `profiles.role` ·
`job_group` · `회원자격` 을 **진짜로 바꿉니다.**

관리자 힘은 `admins` 줄을 뺐다 넣었다 하지 않습니다 — **`is_admin()` 한 줄만** 고칩니다.

```sql
create or replace function is_admin() returns boolean
language sql stable security definer set search_path to 'public' as $$
  select exists (select 1 from admins where profile_id = auth.uid())
     and not exists (select 1 from 마스터페르소나
                      where profile_id = auth.uid() and 지금역할 <> '관리자')
$$;
```

**이 한 줄로 90곳이 전부 따라옵니다.** 페르소나 중에는 관리자 RPC 가 전부
막힙니다. 전환 스위치만 `마스터인가()` 로 따로 열어 둡니다.

### 4-2. 표

```sql
create table 마스터페르소나 (
  profile_id uuid primary key references profiles(id) on delete cascade,
  지금역할    text not null default '관리자',
  바뀐때     timestamptz not null default now()
);
```

지금역할 여덟 — `비회원` · `가입중` · `학생` · `작업치료사` · `물리치료사` ·
`채용담당자` · `교육담당자` · `관리자`.

### 4-3. 로그인

`/master` 에서 **아이디·비번**으로 들어갑니다. 카카오·네이버를 안 씁니다.

```
· 이 계정 하나만. 새 가입 길 없음
· 여러 번 틀리면 잠김 (다섯 번 · 15분)
· 비번은 서버 비밀 설정에만. 저장소·브라우저 코드·이 문서 어디에도 안 적습니다
· 앱스토어 심사용 계정으로도 씁니다
```

**이메일 로그인 제공자를 켜야 합니다.** 지금 Supabase 에 카카오·네이버만 켜져
있습니다. 켜면 일반 회원도 이메일로 가입할 수 있게 되므로, **가입은 막고 로그인만**
열어야 합니다. 이건 세중님 확인이 필요한 설정 변경입니다.

### 4-4. 페르소나로 쓴 글

**회원 화면에서 숨기지 않습니다** — 그 역할의 글로 그대로 남습니다.
관리자에게만 「운영진 작성」 표시가 붙고, 관리자 화면에 모아보기를 만듭니다.

표를 새로 만들지 않습니다. **글쓴이가 마스터 계정인지로 가립니다** —
`posts.author_id` · `comments.author_id` · `chat_messages.sender_id` 를
`마스터페르소나` 와 이어 보면 됩니다. 쓸 때의 역할을 남기려고 칸 하나만 더합니다.

```sql
alter table posts    add column 쓴역할 text;   -- 마스터가 쓴 것만 채웁니다
alter table comments add column 쓴역할 text;
```

모아보기는 페르소나별·날짜별로 묶고 **여러 개 골라 삭제**합니다 (권한 `운영진글`).

### 4-5. 통계 제외

`profiles.excluded = true` 로 둡니다. **여섯 통계 함수가 이미 이 칸을 봅니다** —
`home_stats`·`pay_stats`·`spec_stats`·`salary_stats`·`rookie_salary`·`lang_stats`.

**`admin_stats_now` 만 안 봅니다.** `select count(*) from profiles` 라 회원 수에 1 이
더해집니다. 이번에 **`admin_stats_now` 도 `excluded` 를 보게 고칩니다** (세중님 지시).

### 4-6. 작업지침 8-9 예외

지금 지침은 「시험 자료를 실제 회원 계정에 넣지 않습니다」입니다. 마스터 계정은
**실제 회원이 아니고 통계에서 빠지므로** 예외로 적습니다. 가입 자료는 임의 값으로
끝까지 채웁니다. 지침에 더할 문장은 11절에 적었습니다.

## 5. 교육

### 5-1. 지금

`교육` 110줄은 **긁어 온 목록**입니다 — 제목·날짜·링크뿐이고 신청도 리뷰도 없습니다.
`교육기관` 11곳은 **이름이 열쇠**입니다(`이름 text primary key`).

**그 둘을 건드리지 않습니다.** 새 표를 옆에 세우고, 화면에서 한 줄로 섞어 보여줍니다.
수집한 교육에는 「링크로 가기」, 직접 올린 교육에는 「POTJOB에서 신청 가능」이
붙습니다.

### 5-2. 표

```
교육기관(이름)  ─┬─ 교육과정 ── 교육회차 ─┬─ 교육신청
개인 강사(회원) ─┘                      └─ 교육리뷰 ── 교육리뷰답글
```

```sql
create table 교육과정 (
  과정id    bigserial primary key,
  주최갈래   text not null check (주최갈래 in ('기관','개인')),
  교육기관   text references 교육기관(이름),      -- 기관일 때
  강사       uuid references profiles(id),        -- 개인일 때
  제목       text not null,
  직군       text,
  소개       text,
  만든이     uuid not null,
  만든때     timestamptz not null default now(),
  숨김       boolean not null default false,
  check ((주최갈래='기관' and 교육기관 is not null and 강사 is null)
      or (주최갈래='개인' and 강사 is not null and 교육기관 is null))
);

create table 교육회차 (
  회차id    bigserial primary key,
  과정id    bigint not null references 교육과정(과정id) on delete cascade,
  시작      date not null,
  끝        date,                       -- 여러 날이면 채웁니다
  장소      text,
  정원      int  not null,              -- 필수
  접수시작   date not null,
  접수끝    date not null,
  수강료     int,
  은행      text, 계좌번호 text, 예금주 text,     -- 신청자에게만 보입니다
  입금기한   date,
  입금자명규칙 text,
  환불규정   text not null,
  결제링크   text,
  상태      text not null default '모집중'
            check (상태 in ('모집중','마감','끝남')),
  만든때    timestamptz not null default now(),
  check (접수끝 >= 접수시작 and 접수끝 <= 접수시작 + 30)   -- 공고 기간 최대 30일
);

create table 교육신청 (
  신청id    bigserial primary key,
  회차id    bigint not null references 교육회차(회차id) on delete cascade,
  profile_id uuid not null references profiles(id) on delete cascade,
  상태      text not null default '신청함'
            check (상태 in ('신청함','입금대기','참여확정','미선정')),
  입금눌렀나 boolean not null default false,
  입금누른때 timestamptz,
  신청때    timestamptz not null default now(),
  바뀐때    timestamptz not null default now(),
  unique (회차id, profile_id)
);

create table 교육리뷰 (
  리뷰id    bigserial primary key,
  회차id    bigint not null references 교육회차(회차id) on delete cascade,
  profile_id uuid not null references profiles(id) on delete cascade,
  별점      int  not null check (별점 between 1 and 5),
  글        text not null,

  고친때    timestamptz,
  숨김      boolean not null default false,

create table 교육리뷰답글 (

  profile_id uuid not null,

```

### 5-3. 규칙 — 어디가 막나

```
신청      로그인 회원. 정원이 차면 막힙니다 (참여확정 수 기준)
계좌번호   그 회차에 신청한 사람과 담당자만 — RLS 로 막습니다. 목록 RPC 는 안 내보냅니다
리뷰 쓰기  상태가 '참여확정' 이고, 시작일 오전 8시가 지났을 때만. 기한 없음
리뷰 고치기 쓴 사람만. 몇 번이든
리뷰 지우기 대표 또는 권한 '리뷰삭제'. 담당자는 못 지웁니다 — 답글만
```

### 5-4. 흐름

```
신청 즉시        완료 화면 + 알림 + 「내 신청」에 결제 안내 (상태 '신청함')
「입금했어요」     신청자가 누름 → 담당자 목록에 표시 (상태 '입금대기')
입금 기한 하루 전  안 누른 사람에게 알림
담당자 「참여 확정」 즉시 신청자에게 알림. 확정 수가 정원에 차면 신청 자동 마감
접수 끝나는 날     담당자에게 묻습니다 — 남은 사람 확정할까 · 재공고할까(며칠 · 최대 30일)
「모집 끝내기」     확정 안 된 신청자에게 미선정 알림
```

### 5-5. 결제

**POTJOB 은 결제를 받지 않습니다.** 계좌 안내만 전달합니다. 나중에 바꿀 수 있게
`교육회차.결제링크` 칸만 열어 둡니다.

약관 문구 초안 — 「**결제와 환불은 교육 기관과 신청자 사이의 일이며 POTJOB 은
결제에 관여하지 않습니다.**」 회차 화면과 신청 완료 화면에 둘 다 적고, 「사기 의심
신고」 단추를 답니다.

## 6. 1:1 대화

### 6-1. 지금

**표가 이미 셋 다 있습니다** — `chat_rooms(id, dm_key, created_at)` ·
`chat_members(room_id, profile_id, last_read_at, joined_at)` ·
`chat_messages(id, room_id, sender_id, body, image_path, image_thumb_path, created_at)`.
도우미 함수 `in_room()` · `unread_count()` 도 있습니다. **전부 0줄이고 웹 코드가
한 줄도 없습니다** — 만들다 멈춘 자리입니다. 그대로 씁니다.

비공개 저장소 `chat-images` 도 이미 있습니다.

### 6-2. 더할 것

```sql
alter table chat_rooms
  add column 상태   text not null default '수락' check (상태 in ('신청','수락','거절')),
  add column 건사람 uuid;

alter table chat_messages
  add column 본때 timestamptz;          -- 사진을 상대가 확인한 때

create table 대화차단 (
  막은사람  uuid not null references profiles(id) on delete cascade,
  막힌사람  uuid not null references profiles(id) on delete cascade,
  막은때    timestamptz not null default now(),
  primary key (막은사람, 막힌사람)
);
```

신고는 기존 `reports` 에 `target_type = 'chat'` 으로 넣습니다. 표를 안 늘립니다.

### 6-3. ⚠ 지금 규칙과 부딪힙니다

`밤정리()` 안에 이 줄이 있습니다.

```sql
delete from chat_messages where created_at < now() - interval '1 year';
```

사양은 **30일**이고, **신고된 대화는 보존**입니다. 그래서 이 줄을 이렇게 바꿔야
합니다 — 사진은 30일 뒤 파일과 경로를 지우고, 글은 신고가 없을 때만 지웁니다.
**`delete` 가 들어가므로 승인 창이 뜹니다** (작업지침 8-7).

## 7. 인증 자료

### 7-1. 저장소

지금 비공개 저장소는 `chat-images` 하나뿐이고 **이미지만** 받습니다
(webp·jpeg·png). 사업자등록증은 PDF 가 많습니다. **새로 하나 만듭니다.**

```
이름      proofs
공개      아니오
크기      5MB
받는 것    image/jpeg · image/png · image/webp · application/pdf
```

### 7-2. 표

```sql
create table 인증자료 (
  id        bigserial primary key,
  profile_id uuid not null references profiles(id) on delete cascade,
  자격id     bigint references 회원자격(id) on delete cascade,
  갈래       text not null,      -- 사업자등록증 · 고유번호증 · 사원증 · 재직증명서 ·
                                 -- 활동이력 · 면허증
  경로       text not null,      -- proofs 안 경로
  올린때     timestamptz not null default now(),
  지운때     timestamptz,
  지운까닭   text
);

create table 인증자료열람 (
  id      bigserial primary key,
  자료id   bigint not null references 인증자료(id) on delete cascade,
  누가     uuid not null,
  언제     timestamptz not null default now()
);
```

열람 기록은 **기존 `개인정보접속기록` 에도 한 줄 남깁니다** — 개인정보 접근 기록을
한곳에서 보게. 표 하나를 더 두는 까닭은, 어느 자료를 몇 번 열었는지를 자료 쪽에서
바로 세기 위해서입니다.

### 7-3. 보관과 삭제

```
보관      삭제하지 않습니다. 「기관승인」 권한자만 열 수 있고, 열면 기록이 남습니다
탈퇴      자료를 지웁니다 (파일 + 줄)
예외      신고·분쟁이 진행 중인 계정은 탈퇴해도 끝날 때까지 보존합니다
주민번호   수집하지 않습니다 — 올리는 화면에 「주민번호 뒷자리를 가리고 올려 주세요」.
          확인할 때 보이면 반려하고 다시 올리게 합니다
동의      올리는 화면에 보관 목적·기간 동의 체크. 기존 약관동의 표에 문서 한 종류를 더합니다
```

개인정보처리방침에 더할 문장 초안 —

> **채용·교육 담당자 인증 자료** — 소속을 확인하려고 사업자등록증·재직증명서 등을
> 받습니다. 「기관 회원 승인」 권한을 가진 운영진만 볼 수 있고, 열어 본 기록이
> 남습니다. 회원 탈퇴 시 지웁니다 (신고·분쟁이 진행 중이면 끝난 뒤에 지웁니다).
> **주민등록번호는 받지 않습니다.**

## 11. 기존과 부딪히는 곳

| # | 부딪히는 곳 | 지금 | 어떻게 |
|---|---|---|---|
| 1 | **`is_admin()` 90곳** (함수 55 · 규칙 33 · 뷰 2) | 줄이 있으면 전부 열림 | **고치지 않습니다.** 「운영진인가」로 그대로 두고, 민감한 28곳에 `권한있나()` 를 덧붙입니다. 페르소나는 `is_admin()` **한 줄**만 고쳐 90곳이 따라오게 합니다 |
| 2 | **`profiles.role`** `'현직'\|'학생'` (4명) | 화면이 이 값으로 갈림 | `'채용담당자'` 만 더합니다. 교육 담당자는 `role` 을 안 바꾸고 `회원자격` 으로 붙입니다 — `channelsFor(role)` 과 `/me` 가 안 깨집니다 |
| 3 | **`교육` 110줄 · `교육기관` 11곳** | 긁어 온 목록. 신청·리뷰 없음 | 건드리지 않습니다. 새 표를 옆에 세우고 화면에서 섞습니다. 수집분은 「링크로 가기」, 올린 것은 「POTJOB에서 신청 가능」 |
| 4 | **`교육기관` 의 열쇠가 `이름`(text)** | 글자가 외래키가 됩니다 | 그대로 씁니다. 기관 이름이 바뀌면 `on update cascade` 로 따라가게 합니다. 번호를 새로 붙이면 기존 `교육목록(p_출처)` 을 다 고쳐야 합니다 |
| 5 | **`밤정리()` 가 대화를 1년 뒤 지웁니다** | `delete from chat_messages … interval '1 year'` | 30일로 줄이고 **신고된 대화는 뺍니다.** `delete` 라 승인 창이 뜹니다 (8-7) |
| 6 | **`admin_stats_now` 가 `excluded` 를 안 봅니다** | 회원 수에 마스터 계정이 섞입니다 | 이번에 고칩니다 (세중님 지시) |
| 7 | **비공개 저장소가 `chat-images` 하나** · 이미지만 | 사업자등록증 PDF 를 못 올립니다 | `proofs` 를 새로 만듭니다 (PDF 포함 · 5MB) |
| 8 | **신고 표가 둘** (`reports` · `공고신고`) | 같은 일을 두 벌로 | 합치지 않습니다. 대화·리뷰 신고는 `reports` 에 `target_type` 으로 넣습니다 |
| 9 | **`push_devices` 죽은 표** (0줄 · 코드 없음) | `알림기기` 가 대신 쓰입니다 | 이번 범위 아님. 치울 후보로 적어만 둡니다 |
| 10 | **Supabase 에 이메일 로그인이 꺼져 있습니다** | 카카오·네이버만 | 마스터 계정 때문에 켜야 합니다. **켜면 일반 가입도 열리므로 가입은 막고 로그인만** 열어야 합니다 — 세중님 확인 필요 |

## 12. 세중님이 정해 주실 것

1. **권한 11개 목록이 맞습니까.** 더하거나 뺄 것이 있으면 지금이 쌉니다.
2. **교육 담당자를 `role` 로 두지 않는 것**에 동의하십니까 (3-1). 개인 강사가
   치료사를 겸하는 경우 때문입니다.
3. **이메일 로그인 제공자를 켜도 됩니까** (4-3). 마스터 계정에 필요합니다.
   가입은 막고 로그인만 열겠습니다.
4. **대화 보관 30일**이 맞습니까 — 사진만 30일인지, 글도 30일인지. 지금 `밤정리()`
   는 1년입니다.
5. **채용 담당자의 커뮤니티 접근** — 제안은 **읽기만, 글·댓글은 못 씀**입니다.
   병원 사람이 치료사 방에 글을 쓰면 솔직한 말이 사라집니다. 교육 담당자도 같게 봅니다.
6. **「면허 확인 강사」 배지** — 면허증을 확인한 뒤 **파일을 즉시 지우고** 배지만
   남기는 것으로 하겠습니다 (⑪ 재직 인증과 같은 방식). 맞습니까.
